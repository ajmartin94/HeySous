<objective>
Create a sanitization utility that strips HTML tags and control characters from user-controlled text, then integrate it into the system prompt builder at the two injection points (display names and preference summaries) and wire sanitization logging in the pipeline processor.

Purpose: Prevent user-controlled text from corrupting or injecting content into the Claude system prompt. Per locked decisions, sanitize at read time (system prompt construction), not write time. DB stores original input. Log sanitization events via Pino with a security tag for admin visibility.
Output: `src/ai/sanitize.ts` with `sanitizeForPrompt()` and `sanitizeAndLog()`, integrated into `buildDynamicContext`/`buildPreferenceContext` (sanitization) and `src/pipeline/processor.ts` (logged sanitization).
</objective>

  <name>Task 1: Create sanitization utility and tests</name>
  <files>src/ai/sanitize.ts, tests/ai/sanitize.test.ts</files>
  <action>
Create `src/ai/sanitize.ts` exporting a `sanitizeForPrompt(text: string): string` function that:
1. Strips ALL HTML tags using a regex like `/<[^>]*>/g` replaced with empty string. This removes `<b>`, `</b>`, `<script>`, self-closing tags, etc.
2. Strips null bytes (`\0`) and ANSI escape sequences (`\x1B\[[0-9;]*[a-zA-Z]` pattern).
3. Trims the result (collapsed whitespace at edges).
4. Returns the cleaned string. Empty input returns empty string.

Also export a `sanitizeAndLog(text: string, field: string, logger: Logger): string` wrapper that:
1. Calls `sanitizeForPrompt(text)`.
2. If the result differs from the input, logs at `info` level with structured fields: `{ field, originalLength: text.length, sanitizedLength: result.length, event: "prompt_sanitization" }` and a `security` tag. Use the Pino child logger pattern: `logger.info({ ... }, "Sanitized user input for prompt")`.
3. Returns the sanitized result.

Import the Logger type from `pino` (the project uses pino).

Create `tests/ai/sanitize.test.ts` with tests covering:
- Plain text passes through unchanged
- HTML tags are stripped: `<b>John</b>` -> `John`, `<script>alert(1)</script>` -> `alert(1)`
- Nested/malformed HTML: `<b><i>text</i></b>` -> `text`
- Control characters stripped: null bytes, ANSI escapes like `\x1B[31mred\x1B[0m` -> `red`
- Mixed content: HTML + control chars in one string
- Empty string returns empty string
- String with only tags returns empty string (after trim)
- Normal cooking-related text (ingredient names, unicode) passes through unchanged
- Unicode characters like emoji, accented letters are preserved

Use Vitest. Import with `.js` extension per project convention.

**Step 2: Wire sanitizeAndLog into `src/pipeline/processor.ts` for logging**

The system prompt module does not have a logger instance, but the processor does (`log` from `ProcessorDeps`). Wire `sanitizeAndLog` in the processor BEFORE calling `buildDynamicContext`, so sanitization events are logged per the locked decision.

In `src/pipeline/processor.ts`:

1. Add import: `import { sanitizeAndLog } from "../ai/sanitize.js";`

2. In `processBatch`, in the section where `userName` and `preferences` are prepared (around lines 256-258, after `const preferences = getPreferenceSummaries(...)` and `const userName = ctx.user?.displayName`), add sanitization-with-logging calls:

```typescript
// h. Load user preferences for system prompt injection
const preferences = getPreferenceSummaries(deps.sqlite, householdId);
const rawUserName = ctx.user?.displayName;

// h1. Sanitize user-controlled text with logging (per security policy)
const userName = rawUserName ? sanitizeAndLog(rawUserName, "userName", log) : undefined;
const sanitizedPreferences = preferences.map((pref) => ({
  ...pref,
  title: sanitizeAndLog(pref.title, "preference.title", log),
  summary: sanitizeAndLog(pref.summary, "preference.summary", log),
}));
```

3. Update the `buildDynamicContext` call to use `userName` (already sanitized) and `sanitizedPreferences` instead of raw `preferences`:

```typescript
const dynamicContext = buildDynamicContext({
  preferences: sanitizedPreferences,
  planContext,
  groceryContext,
  reminderContext,
  feedbackContext,
  userName,
  onboardingContext,
  appFeedbackContext,
  dateContext,
});
```

This means sanitization happens at two layers: `sanitizeAndLog` in the processor (for logging), and `sanitizeForPrompt` in the system prompt builder (defense-in-depth). Both use the same underlying `sanitizeForPrompt` -- the processor layer adds logging, the system prompt layer is a safety net. Clean input passes through both layers unchanged with no performance concern.

<task type="auto">
  <name>Task 1: Initialize project and install dependencies</name>
  <files>
    package.json
    tsconfig.json
    .gitignore
    .env.example
  </files>
  <action>
    1. Run `npm init -y` in the project root. Update package.json:
       - Set `"name": "heysous"`
       - Set `"type": "module"` (ESM)
       - Set `"engines": { "node": ">=22" }`
       - Add scripts:
         - `"dev": "tsx watch src/main.ts"`
         - `"start": "node dist/main.js"`
         - `"build": "tsc"`
         - `"db:generate": "drizzle-kit generate"`
         - `"db:push": "drizzle-kit push"`
         - `"db:studio": "drizzle-kit studio"`
         - `"typecheck": "tsc --noEmit"`
         - `"test": "vitest run"`
         - `"test:watch": "vitest"`

    2. Install production dependencies:
       `npm install grammy @grammyjs/parse-mode @grammyjs/auto-chat-action express better-sqlite3 drizzle-orm dotenv pino`

    3. Install dev dependencies:
       `npm install -D typescript @types/node @types/express @types/better-sqlite3 drizzle-kit tsx pino-pretty vitest`

    4. Create tsconfig.json with these exact settings:
       - target: "ES2022"
       - module: "NodeNext"
       - moduleResolution: "NodeNext"
       - strict: true
       - esModuleInterop: true
       - skipLibCheck: true
       - forceConsistentCasingInFileNames: true
       - outDir: "./dist"
       - rootDir: "./src"
       - resolveJsonModule: true
       - declaration: true
       - sourceMap: true
       - include: ["src/**/*"]
       - exclude: ["node_modules", "dist"]

    5. Create .gitignore with: node_modules, dist, .env, data/, *.db, *.db-wal, *.db-shm

    6. Create .env.example with placeholder values:
       ```
       BOT_TOKEN=your_telegram_bot_token_here
       BOT_MODE=polling
       PORT=3000
       WEBHOOK_URL=https://your-domain.com
       DB_FILE_NAME=data/heysous.db
       LOG_LEVEL=info
       NODE_ENV=development
       ```

    7. Create the directory structure (empty directories will be populated in subsequent tasks):
       - src/bot/handlers/
       - src/bot/middlewares/
       - src/telegram/
       - src/db/
       - data/ (for SQLite database files)
  </action>
  <verify>
    - `npm run typecheck` exits with code 0 (may need a placeholder src file first)
    - `node -e "require('./package.json')"` shows the package metadata
    - All dependencies listed in package.json are present in node_modules
  </verify>
  <done>
    package.json has all dependencies, tsconfig.json compiles TypeScript with strict ESM settings, .gitignore excludes sensitive/generated files, .env.example documents all required environment variables.
  </done>
</task>

<task type="auto">
  <name>Task 2: Create config loader and database setup</name>
  <files>
    src/config.ts
    src/db/index.ts
    src/db/schema.ts
    drizzle.config.ts
  </files>
  <action>
    1. Create src/config.ts:
       - Load environment variables using dotenv (call `config()` from dotenv)
       - Export a `config` object with typed fields:
         - `botToken: string` (required, throw if missing)
         - `botMode: "polling" | "webhook"` (default: "polling")
         - `port: number` (default: 3000)
         - `webhookUrl: string` (default: "")
         - `dbFileName: string` (default: "data/heysous.db")
         - `logLevel: string` (default: "info")
         - `isDev: boolean` (true when NODE_ENV !== "production")
       - Validate that BOT_TOKEN is present, throw clear error if not
       - Validate that webhookUrl is set when botMode is "webhook"

    2. Create src/db/schema.ts:
       - Define a `messages` table using Drizzle's sqliteTable:
         - `id`: integer, primary key, auto-increment
         - `chatId`: text, not null (Telegram chat ID as string for BigInt safety)
         - `userId`: text, not null (Telegram user ID as string)
         - `text`: text, not null
         - `direction`: text with enum ["in", "out"], not null
         - `createdAt`: integer in timestamp mode, not null, default to `new Date()`
       - Export the table definition

    3. Create src/db/index.ts:
       - Import Database from better-sqlite3
       - Import drizzle from drizzle-orm/better-sqlite3
       - Import all schema exports
       - Create a function `createDatabase(dbPath: string)` that:
         - Ensures the parent directory exists (use `mkdirSync` with `recursive: true`)
         - Creates the Database instance
         - Enables WAL mode: `sqlite.pragma("journal_mode = WAL")`
         - Returns `drizzle(sqlite, { schema })`
       - Export the function (NOT a singleton -- let main.ts control lifecycle)

    4. Create drizzle.config.ts:
       - Use `defineConfig` from drizzle-kit
       - Set dialect: "sqlite"
       - Set schema: "./src/db/schema.ts"
       - Set out: "./drizzle"
       - Set dbCredentials.url to process.env.DB_FILE_NAME or "data/heysous.db"

    5. Create a minimal src/main.ts entry point that:
       - Imports config
       - Calls createDatabase with config.dbFileName
       - Logs "HeySous starting..." using console.log (pino logger will be used in Plan 02)
       - This is a placeholder that proves the project compiles and runs

    6. Run `npm run db:push` to create the initial database schema (creates the data/ directory and heysous.db file)
  </action>
  <verify>
    - `npx tsx src/main.ts` runs without errors and logs the startup message
    - `npm run typecheck` passes with zero errors
    - `npm run db:push` creates the SQLite database file with the messages table
    - `sqlite3 data/heysous.db ".tables"` shows "messages" (or use `npx drizzle-kit studio` to verify)
  </verify>
  <done>
    Config loads and validates environment variables. Database connection creates a SQLite file with WAL mode enabled. Messages table exists with correct columns. Project compiles and runs end-to-end.
  </done>
</task>

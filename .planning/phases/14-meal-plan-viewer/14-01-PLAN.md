  <name>Task 1: Meal plan API endpoint and router registration</name>
  <files>src/mini-app/routes/meal-plan.ts, src/mini-app/router.ts</files>
  <action>
Create `src/mini-app/routes/meal-plan.ts` following the exact `createRecipeRoutes` factory pattern from `src/mini-app/routes/recipes.ts`:

1. Export `createMealPlanRoutes(sqlite: BetterSqlite3.Database)` factory function that returns `{ getPlan }`.

2. `getPlan` handler for `GET /api/meal-plan?week=current|next`:
   - Read `chatId` from `res.locals.chatId` (set by auth middleware).
   - Read `week` query param, default to `"current"`.
   - Calculate `weekStartDate` (Monday, ISO YYYY-MM-DD format) server-side:
     - Get current date. JS `getDay()` returns 0=Sunday. Convert to Monday-based: `(jsDay + 6) % 7`.
     - Subtract that many days to get this Monday.
     - If `week === "next"`, add 7 days.
     - Format as `YYYY-MM-DD` string using zero-padded month/day.
   - Query with raw SQL (NOT Drizzle ORM -- this codebase's API routes use better-sqlite3 directly):
     ```sql
     SELECT mpe.id, mpe.day_of_week, mpe.meal_type, mpe.recipe_name,
            mpe.knowledge_item_id,
            ki.id AS ki_id
     FROM meal_plan_entries mpe
     JOIN meal_plans mp ON mpe.plan_id = mp.id
     LEFT JOIN knowledge_items ki ON mpe.knowledge_item_id = ki.id
       AND ki.chat_id = mp.chat_id
     WHERE mp.chat_id = ? AND mp.week_start_date = ?
     ORDER BY mpe.day_of_week ASC,
              CASE mpe.meal_type WHEN 'breakfast' THEN 1 WHEN 'lunch' THEN 2 WHEN 'dinner' THEN 3 END ASC
     ```
   - The LEFT JOIN on knowledge_items detects orphaned recipes (knowledge_item_id set but recipe deleted). Return `hasRecipe: ki_id !== null`.
   - ORDER BY includes meal_type ordering so breakfast < lunch < dinner within each day.
   - Return JSON: `{ weekStartDate: string, entries: Array<{ id, dayOfWeek, mealType, recipeName, knowledgeItemId, hasRecipe }> }`
   - Wrap in try/catch, return 500 on error.

3. Register in `src/mini-app/router.ts`:
   - Import `createMealPlanRoutes` from `"./routes/meal-plan.js"` (note .js extension per ESM conventions).
   - After the recipe routes block, add:
     ```typescript
     const mealPlan = createMealPlanRoutes(deps.sqlite);
     router.get("/meal-plan", mealPlan.getPlan);
     ```

Type imports: Use `import type { Request, Response } from "express"` and `import type BetterSqlite3 from "better-sqlite3"` to match existing patterns.

**Date utilities (`mini-app/src/utils/dateUtils.ts`):**

Create client-side date helpers. Duplicate logic from server-side (per prior decision: no shared imports across build boundary).

1. `DAY_NAMES` constant: `["Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday", "Sunday"]`
2. `getTodayIndex(): number` -- returns 0=Monday..6=Sunday using `(new Date().getDay() + 6) % 7`
3. `formatDayHeader(weekStartDate: string, dayOfWeek: number): string` -- takes the API's weekStartDate (ISO YYYY-MM-DD) and a day offset (0-6), returns "Monday, Feb 10" format. Parse date as `new Date(weekStartDate + "T00:00:00")` to avoid timezone shift, add dayOfWeek days, format with `toLocaleDateString("en-US", { month: "short" })`.
4. `isPastDay(dayOfWeek: number, isCurrentWeek: boolean): boolean` -- returns true if the day is before today in the current week. For next week, always returns false.

**Data hook (`mini-app/src/hooks/useMealPlan.ts`):**

Follow the `useRecipes` pattern (isMountedRef, apiFetch, loading/error state):

1. Define types:
   ```typescript
   export interface MealPlanEntry {
     id: number;
     dayOfWeek: number;
     mealType: "breakfast" | "lunch" | "dinner";
     recipeName: string;
     knowledgeItemId: number | null;
     hasRecipe: boolean;
   }

   export interface MealPlanWeek {
     weekStartDate: string;
     entries: MealPlanEntry[];
   }
   ```

2. Hook state:
   - `currentWeek: MealPlanWeek | null` and `nextWeek: MealPlanWeek | null`
   - `activeWeekIndex: number` (0=current, 1=next)
   - `loading: boolean` (true initially)
   - `error: string | null`
   - `selectedRecipeId: number | null` (for recipe detail drill-down)
   - `recipeDetail: RecipeDetailData | null` (reuse type from `useRecipes`)
   - `detailLoading: boolean`
   - `isMountedRef` pattern (same as useRecipes)

3. On mount, fetch BOTH weeks in parallel:
   ```typescript
   const [currentRes, nextRes] = await Promise.all([
     apiFetch("/meal-plan?week=current"),
     apiFetch("/meal-plan?week=next"),
   ]);
   ```
   Parse both responses, set state. This gives instant switching with no loading spinner per research recommendation.

4. `setActiveWeekIndex(index: number)` -- switches displayed week (0 or 1). Used by swipe handler in UI.

5. `openDetail(id: number)` -- sets selectedRecipeId and fetches recipe detail from `/api/recipes/${id}` (reuses the existing recipe detail endpoint). Only callable when entry hasRecipe is true.

6. `closeDetail()` -- clears selectedRecipeId and recipeDetail.

7. Computed getter: `activeWeek` returns `activeWeekIndex === 0 ? currentWeek : nextWeek`.

8. Return: `{ currentWeek, nextWeek, activeWeek, activeWeekIndex, setActiveWeekIndex, loading, error, selectedRecipeId, recipeDetail, detailLoading, openDetail, closeDetail }`

Import `RecipeDetailData` type from `../hooks/useRecipes.js` and `apiFetch` from `../api.js`.

  <action>
Install `@tma.js/init-data-node` in the root project (server-side validation):
```bash
npm install @tma.js/init-data-node
```

Create `src/mini-app/auth-middleware.ts`:
- Import `validate` and `parse` from `@tma.js/init-data-node`
- Export `validateInitData` Express middleware function
- Read `X-Init-Data` header from request
- If missing, return 401 JSON `{ error: "Missing initData" }`
- Call `validate(initData, config.botToken, { expiresIn: 3600 })` (1-hour expiry per INFRA-02)
- On success, call `parse(initData)` and set `res.locals.chatId = String(parsed.user?.id ?? "")`
- If no user in parsed data, return 401 JSON `{ error: "No user in initData" }`
- On validation failure (catch block), return 401 JSON `{ error: "Invalid initData" }`
- Import config from `../config.js` (ESM .js extension required)

Create `src/mini-app/router.ts`:
- Export factory function `createApiRouter(deps)` following project DI pattern
- Deps interface: `{ sqlite: BetterSqlite3.Database }` (repositories created inside from sqlite, same as bot handlers)
- Apply `validateInitData` middleware to all routes via `router.use(validateInitData)`
- Mount summary route at GET `/summary` using `createSummaryRoute(sqlite)`
- Return the Express Router
- Uses factory function pattern consistent with codebase (createGroceryRepository, createServer, etc.)

Create `src/mini-app/routes/summary.ts`:
- Export factory function `createSummaryRoute(sqlite)` that returns a request handler
- Reads `res.locals.chatId` (set by auth middleware)
- Queries counts for the hub dashboard:
  - Grocery: count of unchecked items in active list for this chatId (query grocery_lists JOIN grocery_list_items WHERE status='active' AND checked=0)
  - Recipes: count of knowledge entries of type 'recipe' for this chatId (query knowledge_entries WHERE chat_id=? AND type='recipe')
  - Plans: count of meal plan entries for current week for this chatId (query meal_plans WHERE chat_id=? and date range is current week)
- Returns JSON: `{ grocery: { uncheckedCount }, recipes: { count }, plans: { mealCount } }`
- Uses sqlite.prepare() pattern consistent with existing repositories (NOT Drizzle ORM, matches grocery/repository.ts pattern)

IMPORTANT: All imports must use .js extension (ESM project). Follow the factory function pattern used throughout the codebase.

Update `src/config.ts`:
- Add `miniAppUrl: string` to the Config interface
- Add to config object: `miniAppUrl: process.env.MINI_APP_URL ?? ""` (no validation -- empty string is fine for dev without tunnel)
- This URL is used by bot handlers to construct web_app button URLs (e.g., `https://domain.com/app`)

Update `src/server.ts` -- change the `createServer` function signature to accept additional deps:
- New signature: `createServer(bot, port, deps)` where deps is `{ apiRouter: Router }` (the Router from mini-app/router.ts)
- Import `resolve` from `node:path`
- Import `{ Router } from 'express'` for the type
- Compute `miniAppDist` path: `resolve(import.meta.dirname, '..', 'mini-app', 'dist')`
- ROUTE ORDER IS CRITICAL (Pitfall 5 from research). Register in this exact sequence:
  1. `app.use(express.json())` (existing)
  2. `app.get('/health', ...)` (existing)
  3. `app.use('/app', express.static(miniAppDist))` -- serve built Mini App static files
  4. `app.use('/api', deps.apiRouter)` -- API routes (authenticated)
  5. `app.use('/webhook/...', webhookCallback(...))` (existing)
  6. `app.get('/app/*', (req, res) => res.sendFile(resolve(miniAppDist, 'index.html')))` -- SPA fallback LAST among /app routes
- The SPA fallback must come AFTER static and AFTER API so it only catches client-side routes

Update `src/main.ts`:
- Import `createApiRouter` from `./mini-app/router.js`
- After creating repositories (groceryRepository, planRepository, knowledgeRepository), create the API router:
  ```
  const apiRouter = createApiRouter({ sqlite });
  ```
- Pass apiRouter to createServer: `createServer(bot, config.port, { apiRouter })`
- This happens in the webhook mode block (the `if (config.botMode === "webhook")` branch)
- Also create apiRouter and pass it in polling mode -- even though Mini Apps need webhook mode, having the API available in dev is useful for testing

IMPORTANT: Keep the existing functionality intact. The health check and webhook routes must continue to work. Only ADD new routes.

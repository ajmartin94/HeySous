## Integration Defects

### Defect 1: Fresh Installation Startup Broken

**Severity:** Medium (existing deployments unaffected)
**Location:** `src/db/index.ts:35` → `src/db/migrations.ts` Migration 001
**Issue:** Migration 001 runs `ALTER TABLE knowledge_items ADD COLUMN source_url TEXT` before `initializeFts` creates the `knowledge_items` table. On a fresh database, this throws "no such table: knowledge_items".
**Root Cause:** `runMigrations` at line 35 executes before `initializeFts` at line 44. Migration 001 targets a table that doesn't exist yet on fresh install.
**Affected:** MIGR-01, MIGR-03, IMPORT-04
**Fix:** Guard migration 001 with table existence check (`CREATE TABLE IF NOT EXISTS` or skip if table missing).

### Defect 2: source_url Missing from FTS Retrieval

**Severity:** Low (data stored correctly, not returned via FTS path)
**Location:** `src/knowledge/fts.ts:247` — SELECT omits `source_url`
**Issue:** `getFullItem` SELECT doesn't include `source_url`, so `get_knowledge_item` tool always returns `null` for sourceUrl. The Drizzle repository path (`getById`) returns it correctly.
**Affected:** IMPORT-04
**Fix:** Add `source_url` to the SELECT column list in `getFullItem`.

### Defect 3: BM25 Dedup Threshold Always Triggers

**Severity:** Medium (causes false-positive dedup alerts on every FTS-matched save)
**Location:** `src/ai/tool-handler.ts:130` and `src/knowledge/fts.ts:173`
**Issue:** `searchFts` returns `Math.abs(row.relevance)` making all values positive. Tool handler checks `topMatch.relevance > -5` which is always true for positive numbers. Any FTS match triggers dedup regardless of relevance. Exact title match path works correctly.
**Affected:** KNOW-01, KNOW-04
**Fix:** Invert threshold to `topMatch.relevance < 5` (positive scale, smaller = better), or return raw negative BM25 values.

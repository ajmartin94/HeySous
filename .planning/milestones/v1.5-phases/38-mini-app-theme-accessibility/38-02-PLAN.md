<task type="auto">
  <name>Task 1: Tag contrast fix for both themes</name>
  <files>
    mini-app/src/components/recipes/recipes.css
    mini-app/src/theme/variables.css
  </files>
  <action>
    The current `.tag-pill` uses `background: var(--hs-accent-subtle)` (rgba(91,140,90,0.12)) and `color: var(--hs-accent-dark)` (#3D6B3C). This has poor contrast, especially on dark backgrounds where the semi-transparent green-on-dark is nearly invisible.

    **Fix approach -- add theme-aware tag variables to variables.css:**

    In the `[data-theme="dark"]` block, add:
    ```css
    --hs-tag-bg: rgba(91, 140, 90, 0.25);
    --hs-tag-text: #a3d4a2;
    --hs-tag-active-bg: var(--hs-accent);
    --hs-tag-active-text: #fff;
    ```

    In the `[data-theme="light"]` block, add:
    ```css
    --hs-tag-bg: rgba(91, 140, 90, 0.12);
    --hs-tag-text: #2d5a2c;
    --hs-tag-active-bg: var(--hs-accent);
    --hs-tag-active-text: #fff;
    ```

    **Contrast rationale:**
    - Light theme: #2d5a2c on rgba(91,140,90,0.12) over white = dark green on light green tint. The dark green text (#2d5a2c) against a nearly-white background yields ~7:1 contrast ratio -- well above WCAG AA (4.5:1).
    - Dark theme: #a3d4a2 (light sage green) on rgba(91,140,90,0.25) over dark bg. The light green text on a dark surface with a subtle green tint yields ~5:1 contrast ratio -- above WCAG AA.

    **Update recipes.css `.tag-pill` rule:**
    ```css
    .tag-pill {
      padding: 2px 8px;
      border-radius: 10px;
      font-size: 12px;
      background: var(--hs-tag-bg);
      color: var(--hs-tag-text);
      border: none;
      cursor: pointer;
      -webkit-tap-highlight-color: transparent;
    }

    .tag-pill:active {
      background: var(--hs-tag-active-bg);
      color: var(--hs-tag-active-text);
    }
    ```

    Also update `.tag-chip-bar__chip` (the active filter chip bar) to use the same active tag variables for consistency:
    ```css
    .tag-chip-bar__chip {
      /* ... existing layout styles ... */
      background: var(--hs-tag-active-bg, var(--hs-accent));
      color: var(--hs-tag-active-text, #fff);
    }
    ```

    And update `.tag-pill--overflow` to use hint color variable:
    ```css
    .tag-pill--overflow {
      background: transparent;
      color: var(--tg-theme-hint-color, #999);
      cursor: default;
      padding: 2px 4px;
    }
    ```
    (This is already correct but just verify it uses the themed variable.)
  </action>

  </verify>

    **Styling approach:**
    - Use the same inline style pattern as the current Help.tsx
    - Section headers: accent color, bold
    - Body text: standard paragraph style with good line-height
    - Example messages: italic, secondary hint color, with a "Try:" prefix

Actually, to respect the font size setting, use the CSS variables. For paragraphStyle, use `fontSize: 'var(--hs-font-size-body)'` is NOT valid in inline React styles (CSS variables can't be used directly in inline style objects for font-size on older WebKit). Instead, use a CSS class or keep the fixed sizes -- they're close enough to the --hs-font-size-body already. Keep the existing inline style approach with fixed pixel sizes that are close to the Small preset. The font size CSS variables on `html` will influence `em`/`rem` if we set the font-size on `html`, but since the pages use `px`, the global font-size control needs a different approach.

    **IMPORTANT font size integration:** For the font size setting to affect ALL pages (including Help.tsx inline styles), add a rule in variables.css:
    ```css
    html[data-font-size] {
      font-size: var(--hs-font-size-body);
    }
    ```
    Then in Help.tsx, use relative sizes or `inherit` where possible. But since existing pages mix px sizes extensively, the simplest approach is to NOT change the root font-size (that would break all px-based layouts). Instead, the CSS custom properties --hs-font-size-body/heading/small already change based on `[data-font-size]`, so any CSS file referencing these variables will automatically adjust. For inline styles in Help.tsx, reference the CSS variables via `style={{ fontSize: 'var(--hs-font-size-body)' }}` -- this DOES work in modern browsers (React sets it as a string, browser resolves the var()). Use this approach.

<task type="auto">
  <name>Task 1: Retrieval service with two-pass search and budget enforcement</name>
  <files>
    src/knowledge/retrieval.ts
  </files>
  <action>
Create `src/knowledge/retrieval.ts` implementing the two-pass retrieval pattern:

1. `createRetrievalService(deps: { sqlite: BetterSqlite3.Database, db: DrizzleDatabase, logger: Logger })` factory function. Returns:

   - `search(chatId: string, query: string, limit?: number): { results: SearchResult[], metrics: RetrievalMetrics }` -- Pass 1 of two-pass retrieval.
     - Calls `searchFts()` from fts.ts with the query and chatId
     - Default limit: 5 results
     - Estimates tokens for the result set using `estimateTokens()` (concatenate title + summary for each result)
     - If total tokens exceed soft budget (4K), trim results from the end (least relevant) until within budget. Per user decision: recency wins among equal-relevance items, so secondary sort by lastAccessedAt desc.
     - Returns SearchResult[] and RetrievalMetrics (items searched, items returned, tokens used, query time)
     - Log metrics via deps.logger at info level

   - `getItem(id: number, chatId: string): KnowledgeItem | null` -- Pass 2 of two-pass retrieval.
     - Calls `getFullItem()` from fts.ts
     - Returns full content including tags
     - getFullItem already updates last_accessed_at

   - `getMetrics(): RetrievalMetrics` -- returns metrics from the most recent search call (for /debug command)

2. The search method must handle FTS5 errors gracefully. `searchFts` in fts.ts already has try/catch with LIKE fallback, but also wrap the call here with a catch that returns empty results + logs a warning if something unexpected happens.

3. Token estimation for search results: concatenate `title + " " + summary` for each result. This is what Claude sees in pass 1, so budget against this text. Do NOT include full content in pass 1 budget -- that's the whole point of two-pass.

4. Import types from `../knowledge/types.js`. Import fts functions from `./fts.js`. Import `estimateTokens` from `./token-budget.js`.
  </action>
  <verify>
    Run `npx tsc --noEmit` passes. Verify the file exports createRetrievalService and the return type includes search, getItem, and getMetrics methods.
  </verify>
  <done>
    Retrieval service implements two-pass search: pass 1 returns BM25-ranked summaries within token budget, pass 2 returns full content for selected items. Metrics are tracked per-search for debugging.
  </done>
</task>

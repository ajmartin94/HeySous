<objective>
Add duplicate detection to save_knowledge and input validation to update_knowledge. When saving new knowledge, the tool handler searches for existing items with similar titles using FTS5. If a match is found, it returns match info to Claude instead of creating a duplicate. Claude then presents the match to the user and asks whether to update the existing item or save as new. Also add a skip_dedup parameter so Claude can bypass the check when the user explicitly chooses "save as new".

Purpose: Users should never accidentally create duplicate recipes or preferences. The v1.3 decision established "search-then-suggest with Claude + user deciding" as the correct pattern -- this plan implements it at the tool level.
Output: Modified tool-handler.ts with dedup logic, updated tools.ts with skip_dedup param, updated system-prompt.ts with dedup instructions, and tests.
</objective>

In the `save_knowledge` case, BEFORE the `try` block that creates the item, add dedup logic:

```typescript
case "save_knowledge": {
  const title = input.title as string;
  const summary = input.summary as string;
  const content = input.content as string;
  const tags = input.tags as string[];
  const skipDedup = input.skip_dedup as boolean | undefined;

  // Dedup check: search for existing items with similar titles
  if (!skipDedup && sqlite) {
    try {
      const matches = searchFts(sqlite, title, householdId, 3);

      // Check for exact title match (case-insensitive)
      const exactMatch = matches.find(
        (m) => m.title.toLowerCase() === title.toLowerCase()
      );

      if (exactMatch) {
        return JSON.stringify({
          duplicate_found: true,
          message: `A knowledge item with a very similar title already exists: "${exactMatch.title}" (ID: ${exactMatch.id}). Ask the user if they want to update the existing item or save as new.`,
          existing_item: {
            id: exactMatch.id,
            title: exactMatch.title,
            summary: exactMatch.summary,
          },
        });
      }

      // Check for close FTS match (top result with good relevance)
      if (matches.length > 0) {
        const topMatch = matches[0];
        // BM25 relevance is negative (closer to 0 = better match).
        // Title-weighted search: a score better than -5 with a match suggests strong title overlap.
        if (topMatch.relevance > -5) {
          return JSON.stringify({
            duplicate_found: true,
            message: `Found a similar existing item: "${topMatch.title}" (ID: ${topMatch.id}). Ask the user if they want to update the existing item or save this as a new item.`,
            existing_item: {
              id: topMatch.id,
              title: topMatch.title,
              summary: topMatch.summary,
            },
          });
        }
      }
    } catch {
      // If search fails, proceed with save (dedup is best-effort)
    }
  }

  try {
    // ... existing create logic unchanged
```

IMPORTANT: The `sqlite` parameter is already available in deps but is optional (`sqlite?: BetterSqlite3.Database`). The dedup check is conditional on `sqlite` being available. In production it always is (passed from main.ts), and in tests where it's not provided, dedup gracefully falls back to no-check.

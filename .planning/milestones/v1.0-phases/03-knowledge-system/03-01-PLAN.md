1. Create `src/knowledge/types.ts` with these interfaces:
   - `KnowledgeItem`: { id, chatId, title, summary, content, source (string|null), tags (string[]), createdAt, updatedAt, lastAccessedAt } -- represents a single knowledge item with its tags joined in
   - `SearchResult`: { id, title, summary, relevance (number -- BM25 score), tags (string[]), lastAccessedAt } -- returned from FTS5 search (pass 1 of two-pass retrieval)
   - `RetrievalMetrics`: { itemsSearched, itemsReturned, tokensUsed, queryTimeMs } -- logged via Pino and exposed in /debug
   - `TokenBudgetConfig`: { knowledgeSoftLimit: 4000, knowledgeHardLimit: 6000, conversationBudget: number } -- per user decision: soft ~4K, flex to 6K

2. Create `src/knowledge/schema.ts` with Drizzle tables:
   - `knowledgeItems` table: id (integer PK autoincrement), chatId (text not null), title (text not null), summary (text not null), content (text not null), source (text nullable), createdAt (integer timestamp, default new Date()), updatedAt (integer timestamp, default new Date()), lastAccessedAt (integer timestamp, default new Date())
   - `knowledgeTags` table: id (integer PK autoincrement), knowledgeItemId (integer not null, references knowledgeItems.id with onDelete cascade), tag (text not null)
   - Follow exact patterns from existing `src/db/schema.ts` (integer timestamps with mode "timestamp", $defaultFn, etc.)

3. Update `src/db/schema.ts` to re-export knowledge schema:
   - Add `export { knowledgeItems, knowledgeTags } from "../knowledge/schema.js";` at the bottom
   - This ensures the Drizzle schema object in createDatabase includes knowledge tables

4. Create `src/knowledge/fts.ts` with:
   - `initializeFts(sqlite: BetterSqlite3.Database): void` -- takes the raw better-sqlite3 instance (NOT the Drizzle wrapper)
   - Creates FTS5 virtual table IF NOT EXISTS: `knowledge_fts USING fts5(title, summary, content, content='knowledge_items', content_rowid='id', tokenize='porter unicode61')`
   - Creates 3 sync triggers (AFTER INSERT, AFTER DELETE, AFTER UPDATE on knowledge_items) using the exact SQL from the research doc. Use `CREATE TRIGGER IF NOT EXISTS` -- wait, SQLite doesn't support IF NOT EXISTS for triggers. Instead, wrap each in a try/catch or use `DROP TRIGGER IF EXISTS` before each CREATE TRIGGER.
   - Export a `rebuildFtsIndex(sqlite: BetterSqlite3.Database): void` that runs `INSERT INTO knowledge_fts(knowledge_fts) VALUES('rebuild')` for maintenance.
   - Export `searchFts(sqlite: BetterSqlite3.Database, query: string, chatId: string, limit?: number): SearchResult[]` -- runs the BM25-ranked FTS5 MATCH query, joining with knowledge_items and knowledge_tags. Filter by chatId (per-user knowledge). Weight: title 10x, summary 5x, content 1x via `bm25(knowledge_fts, 10.0, 5.0, 1.0)`. Use `sqlite.prepare().all()` for direct better-sqlite3 access (NOT Drizzle `db.all()` which has unclear return types with raw SQL per research open question).
   - Include `escapeForFts5(query: string): string` -- strip FTS5 operators, wrap terms in double quotes per research Pattern 3. Wrap the MATCH query in try/catch, falling back to a LIKE query on title+summary if FTS5 parse error (per pitfall 1).
   - Export `getFullItem(sqlite: BetterSqlite3.Database, id: number, chatId: string): KnowledgeItem | null` -- pass 2 of two-pass retrieval. Gets full content + tags for a specific item. Also updates `last_accessed_at` to current time (for recency priority).

5. Update `src/db/index.ts`:
   - Import `initializeFts` from `../knowledge/fts.js`
   - After WAL pragma, before `return drizzle(...)`, call `initializeFts(sqlite)` to set up FTS5 tables and triggers
   - Import the knowledge schema in the `* as schema` import -- since we re-exported from db/schema.ts, this happens automatically through the existing `import * as schema from "./schema.js"`

<task type="auto">
  <name>Task 2: Knowledge repository and token budget</name>
  <files>

  <action>
1. Create `src/knowledge/repository.ts`:
   - `createKnowledgeRepository(db: DrizzleDatabase)` factory function (matches codebase pattern)
   - Returns object with methods:
     - `create(chatId: string, item: { title, summary, content, source?, tags: string[] }): KnowledgeItem` -- inserts into knowledgeItems, then inserts each tag into knowledgeTags, returns the created item with tags. Use Drizzle `db.insert().values().returning()` for the main item, then insert tags.
     - `getById(id: number, chatId: string): KnowledgeItem | null` -- gets item with tags joined in. Filter by chatId for security (users only see their own knowledge).
     - `update(id: number, chatId: string, changes: Partial<{ title, summary, content, source, tags }>): KnowledgeItem | null` -- updates specified fields, sets updatedAt to now. If tags provided, delete existing tags and re-insert. Returns updated item.
     - `delete(id: number, chatId: string): boolean` -- deletes item (cascade deletes tags). Returns true if deleted.
     - `listByChatId(chatId: string, limit?: number): KnowledgeItem[]` -- list all items for a chat, ordered by lastAccessedAt desc (recency wins per user decision). Default limit 50.
   - All methods filter by chatId -- knowledge is per-chat, not global.
   - Use Drizzle ORM for all regular table operations. FTS5 queries are in fts.ts, not here.
   - For getting tags with items, use a query that joins knowledgeTags or do a separate select and merge. Drizzle relational queries with `db.query.knowledgeItems.findFirst({ with: { tags: true } })` may work if relations are defined -- but simpler to just do two queries (get item, get tags) and merge, since this is SQLite and it's fast.

2. Create `src/knowledge/token-budget.ts`:
   - `estimateTokens(text: string): number` -- returns `Math.ceil(text.length / 4)` (4 chars/token heuristic per research). Export this.
   - `createTokenBudget(config?: Partial<TokenBudgetConfig>)` factory that returns:
     - `allocate(knowledgeText: string, conversationText: string): { knowledgeTokens: number, conversationTokens: number, withinBudget: boolean }` -- estimates tokens for both, applies priority rule (knowledge > conversation per user decision). If knowledge fits within soft limit (4K), allocate remaining to conversation. If knowledge exceeds soft but within hard (6K), allocate it and reduce conversation. If knowledge exceeds hard limit, truncate to hard limit.
     - `fitItemsWithinBudget(items: Array<{ text: string, lastAccessedAt: Date }>, softLimit?: number, hardLimit?: number): Array<{ text: string, lastAccessedAt: Date }>` -- takes items sorted by relevance, accumulates until budget reached. If a highly relevant item pushes past soft limit but stays under hard limit, include it. Recency breaks ties (most recently accessed first among equal-relevance items).
     - `getConfig(): TokenBudgetConfig` -- returns current config
   - Default config: knowledgeSoftLimit: 4000, knowledgeHardLimit: 6000, conversationBudget: 2000
  </action>

  </verify>

The processor needs to:
1. Track tool calls made during the Claude conversation
2. After response finalization, build deep-link buttons from tracked calls
3. Send buttons as a separate follow-up message

Implementation:

1. Import `buildDeepLinksFromToolCalls` and `buildDeepLinkKeyboard` from `../deep-links/builder.js` at the top of processor.ts.
   Import `DeepLinkTarget` type as well.

2. Inside `processBatch`, before the streaming/non-streaming branch, create a tracking array:
   ```typescript
   const trackedToolCalls: Array<{ name: string; input: Record<string, unknown>; result: string }> = [];
   ```

3. Wrap the `instrumentedHandler` to also track calls. Create a new wrapper AFTER `instrumentedHandler` is created:
   ```typescript
   const trackingHandler = async (name: string, input: Record<string, unknown>): Promise<string> => {
     const result = await instrumentedHandler(name, input);
     trackedToolCalls.push({ name, input, result });
     return result;
   };
   ```
   Pass `trackingHandler` (instead of `instrumentedHandler`) to both `streamMessageWithTools` and `sendMessageWithTools`.

4. After the response finalization section (after `streamSender.finalize()` or `sendFormattedMessage()`, and after saving to messages table -- around the "l2. Edit grocery list message" section), add deep-link button sending:
   ```typescript
   // l3. Send deep-link buttons as follow-up message
   if (trackedToolCalls.length > 0) {
     try {
       // Check for explicit attach_deep_link tool calls first
       const explicitLinks: DeepLinkTarget[] = [];
       for (const tc of trackedToolCalls) {
         if (tc.name === "attach_deep_link") {
           try {
             const parsed = JSON.parse(tc.result) as { deep_link?: boolean; target?: string; recipe_id?: number };
             if (parsed.deep_link && parsed.target) {
               if (parsed.target === "recipe" && parsed.recipe_id) {
                 explicitLinks.push({ type: "recipe", recipeId: parsed.recipe_id });
               } else if (parsed.target === "recipes") {
                 explicitLinks.push({ type: "recipes" });
               } else if (parsed.target === "plan") {
                 explicitLinks.push({ type: "plan" });
               } else if (parsed.target === "grocery") {
                 explicitLinks.push({ type: "grocery" });
               }
             }
           } catch { /* ignore parse errors */ }
         }
       }

       // Build targets from automatic tool tracking (excludes attach_deep_link)
       const autoTargets = buildDeepLinksFromToolCalls(
         trackedToolCalls.filter(tc => tc.name !== "attach_deep_link")
       );

       // Merge: explicit links take priority, deduplicate by type
       const allTargets = [...explicitLinks];
       const existingTypes = new Set(allTargets.map(t => t.type));
       for (const t of autoTargets) {
         if (!existingTypes.has(t.type)) {
           allTargets.push(t);
           existingTypes.add(t.type);
         }
       }

       const keyboard = buildDeepLinkKeyboard(allTargets);
       if (keyboard) {
         // Send as invisible follow-up: Telegram requires text with inline keyboards
         // Use a thin separator message
         await ctx.reply("\u200B", { reply_markup: keyboard });
       }
     } catch (deepLinkError) {
       log.debug(
         { error: deepLinkError instanceof Error ? deepLinkError.message : String(deepLinkError) },
         "Deep-link button send skipped",
       );
     }
   }
   ```

   NOTE: Telegram does not allow empty text with inline keyboards. Use zero-width space ("\u200B") as the text. If Telegram rejects this, fall back to a Unicode thin space or minimal text like "^" -- test and adjust. An alternative is to use `ctx.reply("Open in app:", { reply_markup: keyboard })` for a cleaner UX. Use the phrasing that fits best -- Claude's discretion per CONTEXT.md.

5. This logic goes in BOTH the streaming and non-streaming paths (after finalize/sendFormattedMessage). To avoid duplication, place it after the if/else block (after both paths have completed) but before the token usage logging section (section m). Both paths set `response` and both have the `trackedToolCalls` in scope.

IMPORTANT: The deep-link button sending must be:
- After message finalization (so the button appears after the response)
- Before token logging (order doesn't matter, but logical flow)
- Wrapped in try/catch (never throws -- mirrors processor's NEVER THROW contract)
- Best-effort (log.debug on failure, not error)

Update the reminder sender to include inline keyboard buttons on reminders that reference recipes.

1. Import `buildDeepLinkKeyboard` from `../deep-links/builder.js` at the top of sender.ts.

2. Update the `BotApi` interface to support `reply_markup` in sendMessage options:
   ```typescript
   interface BotApi {
     api: {
       sendMessage: (
         chatId: string,
         text: string,
         options?: { parse_mode?: string; reply_markup?: unknown },
       ) => Promise<unknown>;
     };
   }
   ```
   Note: Using `unknown` for reply_markup avoids importing grammY types into this minimal interface. grammY's `sendMessage` accepts InlineKeyboard objects at runtime.

3. In the `sendReminder` method, after generating the text (step 3) and before sending (step 4), build the keyboard:
   ```typescript
   // 3b. Build deep-link keyboard for recipe-linked reminders
   let replyMarkup: unknown = undefined;
   if (context.knowledgeItemId) {
     const keyboard = buildDeepLinkKeyboard([
       { type: "recipe", recipeId: context.knowledgeItemId as number },
     ]);
     if (keyboard) {
       replyMarkup = keyboard;
     }
   }
   ```

4. Update the sendMessage call in step 4 to include reply_markup:
   ```typescript
   await bot.api.sendMessage(member.telegramId, text, {
     parse_mode: "HTML",
     ...(replyMarkup ? { reply_markup: replyMarkup } : {}),
   });
   ```

5. This applies to ALL reminder types that have a `knowledgeItemId` in their context JSON, which per the CONTEXT.md decision means "any reminder type that mentions a recipe" -- not just cooking reminders. The contextJson for `start_cooking` and `prep_alert` reminders already include `knowledgeItemId` when available (see generator.ts). `morning_summary` reminders include `tomorrowMeals` with `knowledgeItemId` per-meal but these are arrays -- for simplicity, only add the button for single-recipe reminders (start_cooking, prep_alert) where `context.knowledgeItemId` is a top-level field.

  <action>
Create `src/mini-app/routes/admin.ts` exporting `createAdminRoutes(sqlite)` factory (consistent with createGroceryRoutes, createRecipeRoutes pattern).

**Admin guard:** Before each handler, check the requesting user against the admin user IDs configured in `.env`. Import `config` from `../../config.js`. The auth middleware already sets `res.locals.chatId` (their Telegram ID as a string). Check `config.adminUserIds.includes(String(res.locals.chatId))`. Return 403 `{ error: "Admin access required" }` if not in the list. Extract this into a local helper `requireAdmin(res): boolean` that returns true if admin (caller continues) or sends 403 and returns false (caller returns early). No DB lookup needed for the guard — this matches the existing `/costs` command pattern.

**GET /api/admin/activity** — Activity feed endpoint.
Query parameters: `?limit=50&offset=0&type=all&userId=all`
- `type` filter: 'all', 'message', 'tool_call', 'feedback'
- `userId` filter: 'all' or a specific telegram_id

Build a UNION ALL query across multiple sources to create a unified event feed:
1. **Messages** (type='message'): From `messages` table. Fields: id, created_at, 'message' as event_type, chat_id as user_id, direction, text (truncated to 100 chars). Join with `users` table to get display_name.
2. **Token usage / tool calls** (type='tool_call'): From `token_usage` table. Fields: id, created_at, 'tool_call' as event_type, user_id, model, input_tokens, output_tokens, estimated_cost. Join with `users` for display_name.
3. **App feedback** (type='feedback'): From `app_feedback` table. Fields: id, created_at, 'feedback' as event_type, user_id, source, text (truncated to 100 chars). Join with `users` for display_name.

Apply type filter (WHERE clause on event_type) and userId filter. ORDER BY created_at DESC. LIMIT + OFFSET for pagination.

Since UNION ALL with JOINs across tables is complex in a single query, implement as separate queries per event type, merge in JS, sort by timestamp descending, then slice. This is simpler and avoids SQLite UNION quirks.

Return: `{ events: Array<{ id, eventType, userId, userName, timestamp, details }>, hasMore: boolean }`
- `details` is a typed object varying by event type:
  - message: `{ direction, text }`
  - tool_call: `{ model, inputTokens, outputTokens, cost }`
  - feedback: `{ source, text }`

**GET /api/admin/stats** — Usage statistics endpoint.
Query parameter: `?range=today` (today | 7d | 30d)

Compute the time boundary based on range:
- `today`: midnight in SESSION_TIMEZONE (reuse getMidnightEpochSeconds pattern from token-budget-guard.ts — copy the helper locally or extract to a shared util)
- `7d`: 7 * 86400 seconds before now
- `30d`: 30 * 86400 seconds before now

Queries (all scoped to the time boundary):
1. `SELECT COUNT(*) FROM messages WHERE direction = 'in' AND created_at >= ?` — total inbound messages
2. `SELECT COUNT(DISTINCT user_id) FROM messages WHERE direction = 'in' AND created_at >= ?` — active users
3. `SELECT COUNT(*) FROM token_usage WHERE created_at >= ?` — total API calls (tool calls)
4. `SELECT COUNT(*) FROM messages WHERE direction = 'in' AND created_at >= ? AND created_at < ?` — messages per day (group by day using `date(created_at, 'unixepoch')`)
5. Total users: `SELECT COUNT(*) FROM users`
6. Total recipes: `SELECT COUNT(*) FROM knowledge_items ki JOIN knowledge_tags kt ON ki.id = kt.knowledge_item_id WHERE kt.tag = 'recipe'`

For the daily breakdown (charts), query:
```sql
SELECT date(created_at, 'unixepoch') as day, COUNT(*) as count
FROM messages WHERE direction = 'in' AND created_at >= ?
GROUP BY day ORDER BY day
```

Return: `{ summary: { messagesCount, activeUsers, apiCalls, totalUsers, totalRecipes }, daily: Array<{ day, messageCount }> }`

**GET /api/admin/costs** — Cost trends endpoint.
Query parameter: `?range=today` (today | 7d | 30d)

Queries:
1. Total cost in range: `SELECT SUM(estimated_cost) FROM token_usage WHERE created_at >= ?`
2. Per-model breakdown: `SELECT model, SUM(estimated_cost) as cost, SUM(input_tokens + output_tokens) as tokens FROM token_usage WHERE created_at >= ? GROUP BY model`
3. Per-user breakdown: `SELECT user_id, SUM(estimated_cost) as cost FROM token_usage WHERE created_at >= ? GROUP BY user_id` — join with users for display_name
4. Daily cost trend: `SELECT date(created_at, 'unixepoch') as day, SUM(estimated_cost) as cost FROM token_usage WHERE created_at >= ? GROUP BY day ORDER BY day`

Import `config.dailyTokenBudget` for the budget reference line.

Return: `{ totalCost, dailyBudgetTokens, byModel: Array<{ model, cost, tokens }>, byUser: Array<{ userId, userName, cost }>, daily: Array<{ day, cost }> }`

**GET /api/admin/feedback** — Feedback overview endpoint.
Query parameter: `?limit=50&offset=0`

Query: `SELECT af.*, u.display_name FROM app_feedback af LEFT JOIN users u ON af.user_id = u.telegram_id ORDER BY af.created_at DESC LIMIT ? OFFSET ?`

Also: `SELECT COUNT(*) as total FROM app_feedback` for summary.
And: recent trend — count in last 7 days vs previous 7 days.

Return: `{ total, recentCount, entries: Array<{ id, userId, userName, text, source, timestamp }>, hasMore: boolean }`

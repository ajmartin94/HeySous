**2. Update `src/bot/handlers/message.ts`:**

Add a `message:photo` handler alongside the existing `message:text` handler. The photo handler:

a) Gets the largest photo size (last element of `ctx.message.photo` array -- Telegram sends multiple sizes)
b) Downloads the file via grammY's `ctx.api.getFile(fileId)`
c) Constructs the download URL: `https://api.telegram.org/file/bot${ctx.api.token}/${file.file_path}`
d) Fetches the image as a buffer using `fetch()`
e) Base64-encodes the buffer
f) Extracts caption from `ctx.message.caption ?? ""`
g) Enqueues with the base64 image data and mime type "image/jpeg" (Telegram compresses to JPEG)

```typescript
import { logger } from "../../logger.js";

// Inside createMessageHandler, after the message:text handler:

messageHandler.on("message:photo", async (ctx) => {
  const chatId = String(ctx.chat.id);
  const userId = String(ctx.from?.id ?? "unknown");
  const caption = ctx.message.caption ?? "";

  // Get largest photo size (last in array)
  const photos = ctx.message.photo;
  const largest = photos[photos.length - 1];

  try {
    // Download photo via Telegram API
    const file = await ctx.api.getFile(largest.file_id);
    const fileUrl = `https://api.telegram.org/file/bot${ctx.api.token}/${file.file_path}`;

    const response = await fetch(fileUrl);
    if (!response.ok) {
      throw new Error(`Failed to download photo: ${response.status}`);
    }

    const buffer = Buffer.from(await response.arrayBuffer());

    // Check size (5MB limit for Claude vision API)
    if (buffer.length > 5 * 1024 * 1024) {
      await ctx.reply("That photo's a bit large for me to process. Try cropping or sending a smaller version!");
      return;
    }

    const imageBase64 = buffer.toString("base64");

    queue.enqueue(chatId, userId, caption, ctx, processBatch, imageBase64, "image/jpeg");
  } catch (error) {
    logger.error(
      { error: error instanceof Error ? error.message : String(error), chatId },
      "Failed to download photo for processing",
    );
    await ctx.reply("I had trouble downloading that photo. Could you try sending it again?");
  }
});
```

IMPORTANT: The `createMessageHandler` function needs to be `async`-compatible for the photo handler, but since grammY handlers can be async, this works naturally. The text handler remains synchronous (non-blocking).

Change this to handle images. After building `userText`, check if any batch messages have images:

```typescript
// b. Build user message from batch
const userText = batch.messages.map((m) => m.text).filter(Boolean).join("\n\n");

// b2. Check for images in batch
const imageMessages = batch.messages.filter((m) => m.imageBase64);

// ... (existing steps c through e remain unchanged) ...

// f. Construct full messages array: prior history + current user message
// Build content blocks for multimodal messages
const userContent: Anthropic.ContentBlockParam[] = [];

// Add image blocks first (if any)
for (const msg of imageMessages) {
  if (msg.imageBase64 && msg.imageMimeType) {
    userContent.push({
      type: "image" as const,
      source: {
        type: "base64" as const,
        media_type: msg.imageMimeType as "image/jpeg" | "image/png" | "image/gif" | "image/webp",
        data: msg.imageBase64,
      },
    });
  }
}

// Add text block
if (userText) {
  userContent.push({
    type: "text" as const,
    text: userText,
  });
}

const fullMessages: Anthropic.MessageParam[] = [
  ...priorMessages,
  { role: "user" as const, content: userContent.length > 0 ? userContent : userText },
];
```

IMPORTANT: When there are no images and just text, you can keep it as a plain string for efficiency. But when there are images, use the content blocks array format. The simplest approach: always use content blocks if there are images, otherwise use the string format.

RECIPE PHOTO IMPORT:
When a user sends a photo that contains recipe content (cookbook page, handwritten recipe, screenshot):
1. Read the image carefully and extract all recipe information (title, ingredients, instructions, times)
2. Present the extracted recipe to the user in the standard recipe display format

What counts as a recipe photo:
- Cookbook or magazine pages with recipes
- Handwritten recipe cards or notes

What is NOT a recipe photo (respond normally, do NOT extract):
- Photos of cooked dishes or plated food -> "That looks delicious!" + offer to help create a recipe for it
- Photos of ingredients or groceries -> respond conversationally about what they could make
- Non-food photos -> stay in character, respond naturally

If the photo is blurry or hard to read:
- Extract what you can and ask the user to fill in the gaps
- "I could make out most of it, but the ingredients list was a bit blurry. Can you help me fill in a few things?"

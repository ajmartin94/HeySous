  <action>
Create a new `src/memory/` module with three files:

**src/memory/schema.ts** -- Drizzle schema definition for the `memories` table:
- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `household_id` TEXT NOT NULL
- `content` TEXT NOT NULL (the atomic fact, e.g. "Allergic to shellfish")
- `category` TEXT NOT NULL DEFAULT 'general' (one of: dietary, taste, cooking_style, household, schedule, logistics, general)
- `created_at` INTEGER NOT NULL DEFAULT unixepoch()
- `updated_at` INTEGER NOT NULL DEFAULT unixepoch()
- Index on `household_id` for fast lookups

Use the same Drizzle pattern as `src/knowledge/schema.ts` (sqliteTable, text, integer columns).
Re-export from `src/db/schema.ts`.

**src/memory/fts.ts** -- FTS5 virtual table setup and search:
- `initializeMemoryFts(sqlite)` -- Creates `memories` table via raw SQL (CREATE TABLE IF NOT EXISTS), then creates FTS5 virtual table `memories_fts` as external content on the `content` column, plus INSERT/UPDATE/DELETE triggers to keep FTS in sync. Follow the exact same pattern as `initializeFts` in `src/knowledge/fts.ts`.
- `searchMemoryFts(sqlite, householdId, query, limit)` -- FTS5 search returning matching memories with rank score. Filter by household_id. Return `{ id, content, category, rank }[]`.

**src/memory/repository.ts** -- CRUD operations using raw SQLite (same pattern as knowledge repository for FTS-adjacent queries):
- `saveMemory(sqlite, householdId, content, category)` -- INSERT into memories, returns `{ id, content, category }`.
- `updateMemory(sqlite, id, content)` -- UPDATE content and updated_at for a specific memory.
- `deleteMemory(sqlite, id, householdId)` -- DELETE by id with household_id guard. Returns boolean success.
- `getMemoriesByHousehold(sqlite, householdId, limit?)` -- SELECT all memories for a household, ordered by category then created_at DESC. Default limit 200.
- `getMemoryById(sqlite, id, householdId)` -- SELECT single memory by id with household_id guard.

All functions use the factory-free standalone function pattern (like `getPreferenceSummaries` in `src/knowledge/preferences.ts`). All imports use `.js` extensions.

**src/db/migrations.ts** -- Add two new migrations:

Migration v9 `"create-memories-table-and-rename-settings"`:
- Create the `memories` table (same DDL as in fts.ts, but the migration ensures it exists before initializeMemoryFts runs on first boot):
  ```sql
  CREATE TABLE IF NOT EXISTS memories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    household_id TEXT NOT NULL,
    content TEXT NOT NULL,
    category TEXT NOT NULL DEFAULT 'general',
    created_at INTEGER NOT NULL DEFAULT (unixepoch()),
    updated_at INTEGER NOT NULL DEFAULT (unixepoch())
  );
  CREATE INDEX IF NOT EXISTS idx_memories_household ON memories(household_id);
  ```
- Rename `reminder_settings` to `application_settings`: SQLite supports `ALTER TABLE reminder_settings RENAME TO application_settings`. Guard with table existence check first.

Migration v10 `"migrate-preferences-to-memories"`:
- Query all preference-tagged knowledge_items: `SELECT ki.id, ki.household_id, ki.title, ki.summary, GROUP_CONCAT(kt.tag, ',') AS tags FROM knowledge_items ki JOIN knowledge_tags kt ON kt.knowledge_item_id = ki.id WHERE ki.id IN (SELECT knowledge_item_id FROM knowledge_tags WHERE tag = 'preference' OR tag LIKE 'pref:%') GROUP BY ki.id`
- For each row, determine category from tags: `pref:dietary` -> `dietary`, `pref:schedule` -> `schedule`, `pref:cooking`/`pref:budget`/`pref:serving`/`pref:grocery` -> `cooking_style`, `subject:household` -> `household`, else -> `general`. If tag contains `severity:allergy` or `severity:restriction`, prepend the marker to content (e.g., "[ALLERGY] Shellfish allergy").
- Build content string as `"${title}: ${summary}"` for each preference.
- INSERT each into `memories` table.
- DELETE migrated rows from `knowledge_items` (and their tags cascade-delete from `knowledge_tags`).
- Log migration count via the logger import already in migrations.ts.
- Do NOT delete recipe-tagged items (only items where the ONLY relevant tag family is preference/pref:*).

**src/db/index.ts** -- Add `initializeMemoryFts(sqlite)` call after `initializeFts(sqlite)`. Import from `../memory/fts.js`.

**src/db/schema.ts** -- Add re-export: `export * from "../memory/schema.js";`

**IMPORTANT**: All references to `reminder_settings` in other source files (imports, queries, table names) will be updated in Plan 02 alongside the tool rename.

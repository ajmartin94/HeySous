**Defect 1 — Guard migration 001 for fresh install:**

In `src/db/migrations.ts`, migration version 1 (`add-source-url-to-knowledge-items`), wrap the existing logic in a table existence check. Before checking `pragma("table_info(knowledge_items)")`, first check if the table exists at all:

```typescript
up: (sqlite) => {
  // On fresh install, knowledge_items doesn't exist yet (created later by initializeFts).
  // Skip — initializeFts CREATE TABLE now includes source_url.
  const tableExists = sqlite
    .prepare("SELECT name FROM sqlite_master WHERE type='table' AND name='knowledge_items'")
    .get();
  if (!tableExists) return;

  // Existing database: add column if missing
  const columns = sqlite.pragma("table_info(knowledge_items)") as Array<{ name: string }>;
  const hasSourceUrl = columns.some((c) => c.name === "source_url");
  if (!hasSourceUrl) {
    sqlite.exec("ALTER TABLE knowledge_items ADD COLUMN source_url TEXT");
  }
},
```

Then in `src/knowledge/fts.ts`, add `source_url TEXT` to the `CREATE TABLE IF NOT EXISTS knowledge_items` statement (after the `source TEXT,` line). This ensures fresh installs get the column from table creation rather than needing the migration.

**Defect 3 — Fix BM25 threshold comparison:**

In `src/ai/tool-handler.ts`, around line 132, change the BM25 threshold check. Since `searchFts` returns `Math.abs(row.relevance)` (positive values where lower = better match), the comparison must use `<` not `>`:

Change:
```typescript

```
To:
```typescript
if (topMatch.relevance < 5) {
```

Also update the comment above it (line 130-131) to reflect the positive scale:
```typescript
// BM25 relevance is returned as positive values (lower = better match).
// Title-weighted search: a score below 5 suggests strong title overlap.
```

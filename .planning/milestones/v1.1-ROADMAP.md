# Milestone v1.1: Mini Apps

**Status:** SHIPPED 2026-02-10
**Phases:** 11-14
**Total Plans:** 10

## Overview

Add Telegram Mini App visual UIs for grocery lists, recipe browsing, and meal plans while keeping the bot as the primary conversational interface. Hybrid model: bot stays primary for conversation, Mini Apps open from chat buttons for visual tasks like shopping lists and recipe browsing.

## Milestone Summary

**Key Decisions:**
- Hybrid model: bot primary, Mini Apps for visual tasks only
- React+Vite SPA served as static files from existing Express server
- initData HMAC-SHA256 auth for all API requests
- Duplicated constants across server/client (no shared imports across build boundary)
- --legacy-peer-deps for React 19 + @telegram-apps/telegram-ui peer dep conflict
- 8s polling sync for grocery list (avoids WebSocket complexity)
- FTS5 two-step query: bm25() matching separate from GROUP BY tag aggregation
- Parallel dual-week fetch for instant meal plan tab switching

**Issues Resolved:**
- Express 5 named splat parameter for SPA fallback route
- Webhook/polling conflict on startup
- BackButton handler collision between Layout and page components
- Grocery check-off animation timing (800ms delay before state change)
- FTS5 bm25() incompatibility with GROUP BY in any query context (including CTEs)

**Issues Deferred:**
- Recipe "Add to plan" button (complex day/meal-type picker UI) -- v2+
- Item reordering within section (drag-drop unreliable in WebView) -- v2+
- Shared Mini App shell with bottom tab navigation -- v2+

**Technical Debt Incurred:**
- Duplicated SECTION_ORDER and date utility constants across server/client
- --legacy-peer-deps required for React 19 compatibility

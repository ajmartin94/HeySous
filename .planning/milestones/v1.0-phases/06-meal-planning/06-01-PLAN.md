Create `src/planning/schema.ts` with three Drizzle table definitions:

1. `mealPlans` table:
   - id: integer primary key autoIncrement
   - chatId: text not null (chat_id)
   - weekStartDate: text not null (week_start_date) -- ISO date "YYYY-MM-DD", always a Monday
   - createdAt: integer timestamp not null with $defaultFn(() => new Date())
   - updatedAt: integer timestamp not null with $defaultFn(() => new Date())

2. `mealPlanEntries` table:
   - id: integer primary key autoIncrement
   - planId: integer not null (plan_id) with reference to mealPlans.id onDelete cascade
   - dayOfWeek: integer not null (day_of_week) -- 0=Monday through 6=Sunday
   - mealType: text not null (meal_type) with enum ["breakfast", "lunch", "dinner"], default "dinner"
   - recipeName: text not null (recipe_name) -- display name, may or may not match a stored recipe
   - knowledgeItemId: integer (knowledge_item_id) -- optional link to stored recipe
   - createdAt: integer timestamp not null with $defaultFn(() => new Date())

3. `cookingHistory` table:
   - id: integer primary key autoIncrement
   - chatId: text not null (chat_id)
   - recipeName: text not null (recipe_name)
   - knowledgeItemId: integer (knowledge_item_id) -- optional link
   - cookedDate: text not null (cooked_date) -- ISO "YYYY-MM-DD"
   - mealType: text not null (meal_type) with enum ["breakfast", "lunch", "dinner"], default "dinner"
   - source: text not null with enum ["planned", "unplanned"], default "planned"
   - notes: text -- optional
   - createdAt: integer timestamp not null with $defaultFn(() => new Date())

Follow the exact import style from src/knowledge/schema.ts: `import { integer, sqliteTable, text } from "drizzle-orm/sqlite-core";`

Create `src/planning/date-utils.ts`:
- Export `DAY_NAMES` as a const array: ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday", "Sunday"]
- Export `getWeekStartDate(date?: Date): string` -- returns the Monday of the week containing the given date (or today) as "YYYY-MM-DD". Use ISO week rules: Monday = start of week. Algorithm: get day of week, adjust to Monday, format as ISO date string.
- Export `formatDateRange(weekStartDate: string): string` -- takes a Monday ISO date and returns "Mon DD - Mon DD" (e.g., "Feb 10 - Feb 16") for display in plan headers.
- Export `addDays(dateStr: string, days: number): string` -- adds N days to an ISO date string and returns new ISO date string.

Create `src/planning/history.ts`:

1. Export `initializePlanning(sqlite: BetterSqlite3.Database): void` -- runs three CREATE TABLE IF NOT EXISTS statements for meal_plans, meal_plan_entries, and cooking_history. Follow the exact same pattern as `initializeFts` in src/knowledge/fts.ts (raw SQL via sqlite.exec). Include all columns matching the Drizzle schema from Task 1. Make sure to include the foreign key on meal_plan_entries.plan_id referencing meal_plans.id with ON DELETE CASCADE.

2. Export `autoMarkCookedMeals(sqlite: BetterSqlite3.Database, chatId: string): number` -- inserts into cooking_history from meal_plan_entries where the computed cooked_date (week_start_date + day_of_week days) is before today AND no matching cooking_history entry exists yet. Uses `date(mp.week_start_date, '+' || mpe.day_of_week || ' days')` for SQLite date arithmetic. Returns number of rows inserted (result.changes). Use `new Date().toISOString().split("T")[0]` for today's date (server time, per research recommendation).

3. Export `logMeal(sqlite: BetterSqlite3.Database, params: { chatId: string; recipeName: string; cookedDate: string; mealType?: string; knowledgeItemId?: number; notes?: string; source?: string }): void` -- inserts a single row into cooking_history. Default mealType to "dinner", source to "unplanned".

4. Export `getCookingHistory(sqlite: BetterSqlite3.Database, chatId: string, startDate?: string, endDate?: string): CookingHistoryEntry[]` -- queries cooking_history for the chat within the date range. If no dates provided, default to last 3 weeks (21 days). Returns array sorted by cookedDate desc. Define and export the `CookingHistoryEntry` interface (id, recipeName, knowledgeItemId, cookedDate, mealType, source, notes).

Import type for BetterSqlite3: `import type BetterSqlite3 from "better-sqlite3";`

Create `src/planning/repository.ts`:

Export `createPlanRepository(db: DrizzleDatabase)` using the factory function pattern (matches createKnowledgeRepository). The repository returns an object with these methods:

1. `savePlan(chatId: string, weekStartDate: string, entries: PlanEntry[]): SavedPlan` -- Find-or-create the meal_plans row for this chatId + weekStartDate. If plan exists, delete all its entries and update updatedAt. If not, insert new plan row. Then insert all entries. Use Drizzle's `eq()` and `and()` for queries, `.returning().get()` for insert-and-return. Return the plan with its entries.

2. `getPlan(chatId: string, weekStartDate: string): SavedPlan | null` -- Query meal_plans + meal_plan_entries for the given week. Return null if no plan exists. Entries should be ordered by dayOfWeek asc.

3. `getActivePlans(chatId: string): SavedPlan[]` -- Returns current week's plan and next week's plan if they exist. Use getWeekStartDate() from date-utils.ts to compute current week, then compute next week (+7 days). Query for both.

Define and export interfaces:
- `PlanEntry`: { day: number; recipeName: string; mealType?: string; knowledgeItemId?: number }
- `SavedPlan`: { id: number; weekStartDate: string; entries: SavedPlanEntry[] }
- `SavedPlanEntry`: { id: number; dayOfWeek: number; mealType: string; recipeName: string; knowledgeItemId: number | null }

Import DrizzleDatabase type from "../db/index.js". Import schema tables from "./schema.js". Import date utils from "./date-utils.js". Import eq, and from "drizzle-orm".

Create `src/planning/context.ts`:

Format:
- If no plans and no history, return empty string

- If history exists, add "RECENT COOKING HISTORY (last 3 weeks):" section with "- {cookedDate}: {recipeName}" per entry
- Close with `</meal_planning_context>`

Import SavedPlan from "./repository.js", CookingHistoryEntry from "./history.js", DAY_NAMES from "./date-utils.js".

Add the `knowledgeChangelog` table to `src/knowledge/schema.ts`:

```typescript
export const knowledgeChangelog = sqliteTable("knowledge_changelog", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  knowledgeItemId: integer("knowledge_item_id").notNull(),
  // No foreign key -- keep logs even after item deletion
  chatId: text("chat_id").notNull(),
  action: text("action", { enum: ["create", "update", "delete"] }).notNull(),
  changeDescription: text("change_description"),
  previousContent: text("previous_content"),
  createdAt: integer("created_at", { mode: "timestamp" })
    .notNull()
    .$defaultFn(() => new Date()),
});
```

Key: NO foreign key on `knowledgeItemId` -- changelog persists even after the knowledge item is deleted. This is a deliberate design choice per user decision (changelog for data mining, independent of item lifecycle).

Add `ChangelogEntry` type to `src/knowledge/types.ts`:

```typescript
export interface ChangelogEntry {
  id: number;
  knowledgeItemId: number;
  chatId: string;
  action: "create" | "update" | "delete";
  changeDescription: string | null;
  previousContent: string | null;
  createdAt: Date;
}
```

Add CREATE TABLE IF NOT EXISTS for `knowledge_changelog` in `src/knowledge/fts.ts` `initializeFts()`, right after the existing knowledge_tags CREATE TABLE statement:

```sql

  id INTEGER PRIMARY KEY AUTOINCREMENT,
  knowledge_item_id INTEGER NOT NULL,
  chat_id TEXT NOT NULL,
  action TEXT NOT NULL,
  change_description TEXT,
  previous_content TEXT,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())

```

This follows the same pattern as the existing base tables in fts.ts -- raw SQL CREATE TABLE IF NOT EXISTS to ensure the table exists before Drizzle takes over.

**tools.ts:** Add three write tool definitions to the existing KNOWLEDGE_TOOLS array (append after get_knowledge_item):

1. `save_knowledge` -- Creates a new knowledge item. Parameters: title (string, required), summary (string, required), content (string, required), tags (array of strings, required). Description should instruct Claude: "Save a new item to the user's knowledge base (recipe, preference, cooking note). Use this after the user confirms they want to save. Include a descriptive title, a brief summary (1-2 sentences for search results), the full content, and relevant tags. For recipes, tags should include: 'recipe', cuisine type (e.g., 'cuisine:italian'), meal type (e.g., 'meal:dinner'), protein (e.g., 'protein:chicken'), and difficulty (e.g., 'difficulty:easy'). Returns the saved item's ID."

2. `update_knowledge` -- Updates an existing knowledge item. Parameters: id (number, required), title (string, optional), summary (string, optional), content (string, optional), tags (array of strings, optional), change_description (string, optional -- brief note of what changed). Description should instruct Claude: "Update an existing knowledge item. Provide the item ID and only the fields that changed. IMPORTANT: the content field replaces the ENTIRE content -- for partial recipe updates, first retrieve the current content with get_knowledge_item, modify the specific part, then send back the complete updated content. Does NOT require re-confirming the whole recipe for minor changes."

3. `delete_knowledge` -- Deletes a knowledge item permanently. Parameters: id (number, required). Description: "Delete a knowledge item permanently. Only use after user explicitly confirms deletion. Returns success/failure."

Follow the exact same Anthropic.Tool type pattern as existing tools. Use `type: "object" as const` for input_schema.

```typescript

  knowledgeRepository: ReturnType<typeof createKnowledgeRepository>;
```

Add imports for: `createKnowledgeRepository` from `../knowledge/repository.js`, `DrizzleDatabase` from `../db/index.js`, `knowledgeChangelog` from `../knowledge/schema.js`.

Add three new cases to the switch statement in `handleToolCall`:

**case "save_knowledge":** Extract title, summary, content, tags from input. Call `knowledgeRepository.create(chatId, { title, summary, content, tags })`. Then log to changelog: `db.insert(knowledgeChangelog).values({ knowledgeItemId: item.id, chatId, action: "create", changeDescription: "Created: " + title }).run()`. Return JSON: `{ message: "Saved \"${title}\" (ID: ${item.id})", id: item.id }`.

**case "update_knowledge":** Extract id and optional title, summary, content, tags, change_description. First call `knowledgeRepository.getById(id, chatId)` -- if null, return error JSON `{ error: "No item found with ID ${id}" }`. Save previous content for changelog. Call `knowledgeRepository.update(id, chatId, changes)` where changes is built from the optional fields (title, summary, content, tags -- only include if defined). If update returns null, return error. Log changelog with action "update", the change_description from input (or a generated one listing which fields changed), and previousContent from the pre-update snapshot. Return JSON: `{ message: "Updated \"${updated.title}\" (ID: ${id})", id: updated.id }`.

**case "delete_knowledge":** Extract id. First call `knowledgeRepository.getById(id, chatId)` for changelog snapshot -- if null, return error. Call `knowledgeRepository.delete(id, chatId)`. Log changelog with action "delete", changeDescription "Deleted: " + previous.title, previousContent as the full previous content. Return JSON: `{ message: "Deleted \"${previous.title}\"", deleted: true }`.

All return values are JSON.stringify'd strings per existing convention.

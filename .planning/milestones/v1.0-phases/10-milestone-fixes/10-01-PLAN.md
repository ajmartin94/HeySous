<task type="auto">

Four files to edit:

1. src/bot/handlers/costs.ts (lines 24-27): The admin check currently compares String(ctx.from?.id) against config.adminUserIds. ADMIN_USER_IDS may contain Telegram usernames (strings like "ajmartin94") OR numeric user IDs. Fix the check to support both:
   ```typescript
   const numericId = String(ctx.from?.id ?? "");
   const username = ctx.from?.username ?? "";
   const isAdmin = config.adminUserIds.some(
     (adminId) => adminId === numericId || (username && adminId.toLowerCase() === username.toLowerCase())
   );
   if (!isAdmin) {
     return;
   }
   ```
   This allows ADMIN_USER_IDS to contain either "123456789" (numeric) or "ajmartin94" (username), and both will match.

2. src/bot/handlers/preferences.ts (line 90): formatPreferenceLine() currently returns `- ${pref.title}${markerSuffix}` which shows only the title. Change to include the summary:
   ```typescript
   return `- <b>${pref.title}</b>${markerSuffix}: ${pref.summary}`;
   ```
   This shows "- **No shellfish** [ALLERGY]: Allergic to all shellfish including shrimp and crab" instead of just "- No shellfish [ALLERGY]".

3. src/knowledge/preferences.ts (line 37): The SQL WHERE clause uses `kt.tag = 'preference'` which requires an exact match. Preferences are tagged with both 'preference' AND 'pref:dietary', 'pref:schedule', etc. The issue is that some preferences may only have pref:* tags without the exact 'preference' tag. Broaden the filter:
   ```sql
   WHERE ki.chat_id = ? AND (kt.tag = 'preference' OR kt.tag LIKE 'pref:%')
   ```
   This ensures preferences tagged with any pref:* domain tag are also found even if the base 'preference' tag was omitted.

4. .env.example (line 12): Update the ADMIN_USER_IDS comment to clarify both formats are supported:
   ```
   # Admin access (comma-separated Telegram numeric user IDs or usernames, e.g. "123456789,ajmartin94")
   ADMIN_USER_IDS=
   ```
  </action>

<task type="auto">
  <name>Task 1: Add recipe variation handling section to system prompt</name>
  <files>src/ai/system-prompt.ts</files>
  <action>
Add a new `RECIPE_VARIATIONS_PROMPT` constant in `src/ai/system-prompt.ts` and append it to the system prompt output in `buildSystemPrompt()`.

The prompt section should be wrapped in `<recipe_variations>` XML tags and cover:

1. **IN-PLACE MODIFICATIONS** (tweaks to an existing recipe):
   - When a user asks to modify a recipe ("make it spicier", "less salt", "try a different cooking method"), Sous should:
     a. Use `get_knowledge_item` to retrieve the current recipe content
     b. Modify the specific part of the recipe content (not rewrite the whole thing)
     c. Use `update_knowledge` to save the modified content back
     d. Confirm the change naturally: "Done, I bumped up the chili flakes in your stir fry!"
   - Do NOT create a new recipe card for tweaks. Update the existing one.
   - Include a `change_description` in the update_knowledge call (e.g., "Increased chili flakes from 1 tsp to 1 tbsp per user request")

2. **INLINE SUBSTITUTION NOTES** (interchangeable ingredients):
   - When a user mentions alternatives ("this works with chicken or tofu", "you can use shrimp instead"), add substitution notes to the recipe content
   - Format substitution notes as a "Variations" section at the end of the recipe content (after Notes, before any Feedback section):
     ```
     Variations:
     - Protein: chicken (default), tofu, shrimp
     - Heat level: mild (default) / add 1 tbsp sriracha for spicy
     - Sauce: teriyaki (default), peanut sauce, sweet chili
     ```
   - Each variation line should list the default option first, then alternatives
   - This is user-driven: the user mentions alternatives or asks Sous to suggest some. Sous does NOT proactively suggest adding substitution notes unprompted.

3. **MEAL PLAN INTEGRATION WITH SUBSTITUTIONS**:
   - When adding a recipe that has a Variations section to a meal plan, pick the first-listed (default) option
   - After saving the plan, briefly mention the alternatives: "I put chicken stir fry on Tuesday -- want tofu or shrimp instead?"
   - If the user requests a specific variant for a meal plan entry, honor it but keep the recipe card's default unchanged

4. **WHAT NOT TO DO**:
   - Do NOT create separate recipe cards for each variant (no "Chicken Stir Fry" + "Tofu Stir Fry" as separate items)
   - Do NOT proactively suggest adding substitution notes when saving a new recipe -- only when the user explicitly mentions alternatives
   - Do NOT modify a recipe's substitution notes unless the user asks

Append `${RECIPE_VARIATIONS_PROMPT}` to the return value in `buildSystemPrompt()`, placing it right after `${FEEDBACK_PROMPT}` and before `${APP_FEEDBACK_PROMPT}`.

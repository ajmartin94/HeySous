1. Create `src/mini-app/routes/recipes.ts` following the `grocery.ts` factory pattern exactly:
   - Import: `type { Request, Response }` from express, `type BetterSqlite3` from better-sqlite3, `escapeForFts5` from `../../knowledge/fts.js`.
   - Export `createRecipeRoutes(sqlite: BetterSqlite3.Database)` returning an object with two handlers.
   - All handlers read `const chatId = res.locals.chatId as string;`.

   **getList** handler (for GET /api/recipes):
   - Read query params: `const { q, tag, sort, limit } = req.query`
   - Default limit to 50: `const maxResults = Math.min(Number(limit) || 50, 100)`
   - Default sort to "recent": `const sortBy = (sort as string) || 'recent'`
   - Build the SQL query dynamically based on which params are present. Four paths:

   **Path A -- No search, no tag filter (base query):**
   ```sql
   SELECT ki.id, ki.title, ki.summary, ki.updated_at,
          GROUP_CONCAT(DISTINCT kt.tag) AS tags,
          (SELECT MAX(ch.cooked_date) FROM cooking_history ch
           WHERE ch.knowledge_item_id = ki.id AND ch.chat_id = ki.chat_id) AS last_cooked,
          (SELECT COUNT(*) FROM cooking_history ch
           WHERE ch.knowledge_item_id = ki.id AND ch.chat_id = ki.chat_id) AS cook_count
   FROM knowledge_items ki
   JOIN knowledge_tags kt ON kt.knowledge_item_id = ki.id
   WHERE ki.chat_id = ?
     AND ki.id IN (SELECT knowledge_item_id FROM knowledge_tags WHERE tag = 'recipe')
   GROUP BY ki.id
   ```

   **Path B -- Tag filter only (no search):**
   Same as Path A but add: `AND ki.id IN (SELECT knowledge_item_id FROM knowledge_tags WHERE tag = ?)`

   **Path C -- Search only (no tag filter):**
   Use `escapeForFts5(q as string)`. If escaped is empty, return empty results.
   ```sql
   SELECT ki.id, ki.title, ki.summary, ki.updated_at,
          GROUP_CONCAT(DISTINCT kt.tag) AS tags,
          bm25(knowledge_fts, 10.0, 5.0, 1.0) AS relevance,
          (SELECT MAX(ch.cooked_date) FROM cooking_history ch
           WHERE ch.knowledge_item_id = ki.id AND ch.chat_id = ki.chat_id) AS last_cooked,
          (SELECT COUNT(*) FROM cooking_history ch
           WHERE ch.knowledge_item_id = ki.id AND ch.chat_id = ki.chat_id) AS cook_count
   FROM knowledge_fts
   JOIN knowledge_items ki ON ki.id = knowledge_fts.rowid
   JOIN knowledge_tags kt ON kt.knowledge_item_id = ki.id
   WHERE knowledge_fts MATCH ?
     AND ki.chat_id = ?
     AND ki.id IN (SELECT knowledge_item_id FROM knowledge_tags WHERE tag = 'recipe')
   GROUP BY ki.id
   ```
   When search is active, default sort should be by relevance (ignore sort param for FTS results -- BM25 relevance is most useful). But if sort is explicitly 'alphabetical' or 'most_cooked', honor it.

   **Path D -- Search + tag filter:**
   Same as Path C but add the tag subquery: `AND ki.id IN (SELECT knowledge_item_id FROM knowledge_tags WHERE tag = ?)`

   **Sorting** (append ORDER BY based on sortBy):
   - `'recent'`: `ORDER BY ki.updated_at DESC`
   - `'alphabetical'`: `ORDER BY ki.title ASC`
   - `'most_cooked'`: `ORDER BY cook_count DESC, ki.title ASC`
   - When FTS active and sort is 'recent': `ORDER BY relevance ASC` (BM25 lower = better)

   Append `LIMIT ?` to all queries.

   **Response format:**
   Map rows to: `{ id, title, summary, tags: row.tags ? row.tags.split(',') : [], lastCooked: row.last_cooked || null, cookCount: row.cook_count || 0 }`
   Return `res.json({ recipes })`.

   Wrap the FTS queries in a try/catch -- on FTS5 parse error, fall back to Path A/B (non-search).

   **getDetail** handler (for GET /api/recipes/:id):
   - Read `const id = Number(req.params.id)`. If isNaN, return `res.status(400).json({ error: "Invalid recipe ID" })`.
   - Query for the full recipe:
   ```sql
   SELECT ki.id, ki.title, ki.summary, ki.content, ki.updated_at,
          GROUP_CONCAT(DISTINCT kt.tag) AS tags,
          (SELECT MAX(ch.cooked_date) FROM cooking_history ch
           WHERE ch.knowledge_item_id = ki.id AND ch.chat_id = ki.chat_id) AS last_cooked,
          (SELECT COUNT(*) FROM cooking_history ch
           WHERE ch.knowledge_item_id = ki.id AND ch.chat_id = ki.chat_id) AS cook_count
   FROM knowledge_items ki
   JOIN knowledge_tags kt ON kt.knowledge_item_id = ki.id
   WHERE ki.id = ? AND ki.chat_id = ?
   GROUP BY ki.id
   ```
   - If no row, return `res.status(404).json({ error: "Recipe not found" })`.
   - DO NOT update last_accessed_at for browse (per research anti-pattern). Actually, it's acceptable per research note -- but skip it for the list endpoint. For detail, update is fine: `sqlite.prepare('UPDATE knowledge_items SET last_accessed_at = ? WHERE id = ? AND chat_id = ?').run(Math.floor(Date.now() / 1000), id, chatId)`.
   - Map: `{ id, title, summary, content: row.content, tags: row.tags ? row.tags.split(',') : [], lastCooked: row.last_cooked || null, cookCount: row.cook_count || 0 }`
   - Return `res.json({ recipe })`

1. Create `mini-app/src/utils/recipeParser.ts`:

   **Types:**
   ```typescript
   export interface IngredientGroup {
     heading: string | null;  // null = no sub-section header
     items: string[];
   }

   export interface FeedbackEntry {
     date: string;
     sentiment: 'positive' | 'neutral' | 'negative';
     notes: string;
   }

   export interface ParsedRecipe {
     ingredientGroups: IngredientGroup[];
     steps: string[];
     metadata: {
       prepTime?: string;
       cookTime?: string;
       totalTime?: string;
       servings?: string;
     };
     notes: string[];
     feedback: FeedbackEntry[];
   }
   ```

   **parseRecipeContent(content: string): ParsedRecipe:**
   - Split content by newlines. Track `currentSection` ('' | 'ingredients' | 'steps' | 'notes' | 'feedback').
   - Detect section headers with case-insensitive regex: `/^ingredients:/i`, `/^steps:/i`, `/^notes:/i`, `/^feedback:/i`.
   - Detect metadata lines not under a section: `/^(prep time|cook time|total time|servings):\s*(.+)/i` -- map to metadata fields.
   - For ingredients section:
     - Lines ending with `:` that don't start with `-` are sub-section headers (e.g., "For the crust:"). Push current group if it has items, start new group.
     - Lines starting with `-` are ingredient items. Strip the leading `- ` and add to current group.
   - For steps section: Strip leading `\d+[.)] ` prefix. Push non-empty text to steps array.
   - For notes section: Strip leading `- ` if present. Push to notes array.
   - For feedback section: Parse with regex `/^-\s*(\d{4}-\d{2}-\d{2})\s*\[(\w+)\]:\s*(.+)/`. Push matching entries.
   - After loop, push final ingredient group if it has items.
   - Return ParsedRecipe. Be defensive: all sections optional, handle empty content gracefully.

   **computeRating(feedback: FeedbackEntry[]): { netScore: number; total: number; label: string | null } | null:**
   - If feedback is empty, return null.
   - Count positive and negative entries.
   - netScore = positive - negative, total = feedback.length.
   - Derive label: `total >= 2 && netScore >= 2` -> 'favorite', `netScore > 0` -> 'liked', `netScore === 0 && total > 0` -> 'mixed', `netScore < 0` -> 'needs work'.
   - Return `{ netScore, total, label }`.

2. Create `mini-app/src/hooks/useRecipes.ts`:
   Follow the `useGroceryList.ts` pattern exactly (isMountedRef, apiFetch, loading/error state).

   **Types (define locally):**
   ```typescript
   export interface RecipeCard {
     id: number;
     title: string;
     summary: string;
     tags: string[];
     lastCooked: string | null;
     cookCount: number;
   }

   export interface RecipeDetailData {
     id: number;
     title: string;
     summary: string;
     content: string;
     tags: string[];
     lastCooked: string | null;
     cookCount: number;
   }

   export type SortOption = 'recent' | 'alphabetical' | 'most_cooked';
   ```

   **useRecipes() hook:**
   - State: `recipes: RecipeCard[]`, `loading: boolean`, `error: string | null`, `searchInput: string` (raw input), `debouncedQuery: string` (debounced), `activeTag: string | null`, `sortBy: SortOption`, `selectedRecipeId: number | null`, `recipeDetail: RecipeDetailData | null`, `detailLoading: boolean`.
   - Use `isMountedRef` pattern (same as useGroceryList).
   - **Debounce:** useEffect that sets debouncedQuery from searchInput after 300ms. Cleanup clears timeout.
   - **fetchRecipes:** useCallback that builds query string from debouncedQuery, activeTag, sortBy. Calls `apiFetch('/recipes?...')`. Parses response, updates recipes state. Sets loading false. Handles errors.
   - **fetchDetail:** useCallback(async (id: number)) that calls `apiFetch('/recipes/${id}')`. Sets detailLoading true, then false. Updates recipeDetail state.
   - **Effect to trigger fetchRecipes:** Depends on `[debouncedQuery, activeTag, sortBy]`.
   - **Effect for initial load:** Fetch recipes on mount.
   - **setSearchInput:** Direct state setter for the raw input value.
   - **setActiveTag:** State setter for tag filter. Setting to the same tag toggles it off (sets null).
   - **setSortBy:** State setter for sort option.
   - **openDetail(id):** Sets selectedRecipeId and calls fetchDetail(id).
   - **closeDetail():** Sets selectedRecipeId to null, recipeDetail to null.

   **Return:**
   ```typescript
   {
     recipes, loading, error,
     searchInput, setSearchInput,
     activeTag, setActiveTag,
     sortBy, setSortBy,
     selectedRecipeId, recipeDetail, detailLoading,
     openDetail, closeDetail,
   }
   ```

   Import `apiFetch` from `'../api.js'`.

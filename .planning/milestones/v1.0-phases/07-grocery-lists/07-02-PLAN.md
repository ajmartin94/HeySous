Three tools:

1. `save_grocery_list` -- Creates a new grocery list from scratch. Claude sends ALL items after aggregating ingredients from meal plan recipes. Each item has: name (string, required), quantity (string, optional -- freeform like "2 lbs"), store (string, required -- user-defined store name), section (string, required -- "Produce", "Dairy", "Meat", "Pantry", "Bakery", "Frozen", "Beverages", etc.).
   - input_schema: { items: array of { name, quantity?, store, section } } -- required: ["items"]
   - Description should mention: "Creates a new grocery list, replacing any existing active list. Send ALL items with store assignment, section, and quantity. Stores are user-defined (not hardcoded). Sections are categories like Produce, Dairy, Meat, Pantry, Bakery, Frozen, Beverages."

2. `update_grocery_list` -- Modify the active list. Supports four optional actions: add_items (array of {name, quantity?, store, section}), remove_item_ids (array of numbers), check_item_ids (array of numbers), uncheck_item_ids (array of numbers). At least one action must be provided.
   - input_schema: { add_items?, remove_item_ids?, check_item_ids?, uncheck_item_ids? } -- required: []
   - Description should mention: "Update the active grocery list. Use for the pantry check (removing items user has), adding extras (snacks, drinks), or checking off items conversationally."

3. `get_grocery_list` -- Returns the active list with all items, their store/section/quantity/checked status and item IDs.
   - input_schema: { properties: {} } -- required: []
   - Description: "Get the active grocery list with all items, their IDs, stores, sections, quantities, and checked status."

Update src/ai/tool-handler.ts:

1. Add groceryRepository as an optional dependency in the createToolHandler deps interface (same pattern as planRepository being optional):
   ```
   groceryRepository?: ReturnType<typeof createGroceryRepository>;
   ```
   Import createGroceryRepository type from "../grocery/repository.js".

2. Add three new switch cases in handleToolCall:

   case "save_grocery_list":
   - Check groceryRepository exists (return error if not)
   - Extract items array from input
   - Call groceryRepository.createList(chatId) to create a new list (deactivates old)
   - Call groceryRepository.addItems(list.id, items) to add all items
   - Return JSON with { message, listId, itemCount: items.length }

   case "update_grocery_list":
   - Check groceryRepository exists
   - Get active list via groceryRepository.getActiveList(chatId)
   - If no active list, return error
   - Process each action if provided:
     - add_items -> groceryRepository.addItems(list.id, items)
     - remove_item_ids -> groceryRepository.removeItems(ids)
     - check_item_ids -> groceryRepository.checkItems(ids)
     - uncheck_item_ids -> groceryRepository.uncheckItems(ids)
   - Fetch updated items via groceryRepository.getListItems(list.id)
   - Return JSON with { message: "List updated", listId: list.id, messageId: list.messageId, items: full item array with id/name/quantity/store/section/checked }
   - IMPORTANT: Include messageId in the response -- the processor needs this to edit the Telegram message in place after conversational check-off

   case "get_grocery_list":
   - Check groceryRepository exists
   - Get active list
   - If no list, return { message: "No active grocery list" }
   - Get all items
   - Return JSON with { listId, status, items: array with id/name/quantity/store/section/checked }

IMPORTANT: Use .js extensions on all local imports. Tool handler remains synchronous -- all repository calls use raw SQLite.

- Query: SELECT gl.id, gl.status, COUNT(gli.id) as total_items, SUM(CASE WHEN gli.checked = 1 THEN 1 ELSE 0 END) as checked_items, GROUP_CONCAT(DISTINCT gli.store) as stores FROM grocery_lists gl LEFT JOIN grocery_list_items gli ON gli.list_id = gl.id WHERE gl.chat_id = ? AND gl.status = 'active' GROUP BY gl.id LIMIT 1
- If no active list, return empty string
- Return formatted context string:

```
<grocery_context>
Active grocery list: {total_items} items across {store_count} store(s) ({store_names}), {checked_items} checked off.
</grocery_context>
```

This is a lightweight summary (not full item list) to keep system prompt tokens low. Claude calls get_grocery_list when it needs full details.

```
<grocery_list_management>
You help users generate and manage grocery lists from their meal plans.

GENERATING A GROCERY LIST:
- When the user asks for a grocery list, first get their active meal plan (via get_meal_plan)
- For each recipe in the plan, search and retrieve the full recipe to get ingredients (via search_knowledge + get_knowledge_item)
- AGGREGATE ingredients across recipes: if 3 recipes need onions, combine into one entry with total quantity
- Read the user's store preferences from <user_preferences> to assign items to the correct stores
- If the user has a default store preference, unassigned items go there
- If no store preferences exist, put everything under a single "Grocery" store and ask what stores they shop at
- Categorize items into sections: Produce, Dairy, Meat, Pantry, Bakery, Frozen, Beverages, etc.
- Call save_grocery_list with ALL items at once

AFTER GENERATING:
- After saving the list, prompt the "check the pantry" step: "Here's your list! Take a look and let me know what you already have at home, or if you need to add anything (snacks, drinks, etc.)"
- When the user says they have items, use update_grocery_list with remove_item_ids to remove them
- When the user wants to add extras, use update_grocery_list with add_items -- mix extras into appropriate store sections (NOT a separate "Other" section)
- The pantry check is conversational and optional -- if the user says "looks good", move on

LIST DISPLAY FORMAT:
- Single message with store headers as top-level bold sections
- Items grouped by store section within each store (italic section headers)
- Item format: quantity + item only (no recipe source attribution)
- Example:
  <b>Kroger</b>
  <i>Produce</i>
  - 3 onions
  - 2 lbs chicken breast
  <i>Dairy</i>
  - 1 gallon milk

CHECKING OFF ITEMS:
- Users can check off items conversationally: "got the chicken and onions", "got everything from produce"
- Use update_grocery_list with check_item_ids to mark items
- Users can also tap inline buttons on the list message to check off items
- To undo: use uncheck_item_ids
- No special interaction when all items are checked

USING GROCERY TOOLS:
- save_grocery_list: Creates a NEW list (replaces any existing active list). Always send ALL items.
- update_grocery_list: Modify the active list. Returns updated items with messageId for display refresh.
- get_grocery_list: Retrieve active list. Use when you need to see current state (e.g., user asks "what's left on my list?").

STORE PREFERENCES:
- Store preferences are stored as regular user preferences (knowledge items tagged "preference" + "pref:grocery")
- When a user says "I get meat at Costco", save that as a preference via save_knowledge
- Default store preference has the "default-store" tag
- Always check preferences before generating a list
</grocery_list_management>
```

  <name>Task 2: Memory FTS5 search and dedup threshold tests</name>
  <files>tests/memory/fts.test.ts</files>
  <behavior>
    - searchMemoryFts returns matching memories ranked by BM25 relevance
    - searchMemoryFts filters by householdId (cross-household isolation)
    - searchMemoryFts returns empty array for empty/whitespace query
    - searchMemoryFts returns empty array when no matches exist
    - searchMemoryFts respects limit parameter
    - searchMemoryFts handles special characters in query without crashing (FTS5 operator escaping)
    - searchMemoryFts falls back to LIKE when FTS5 parse fails (verified by rank=0 in results)
    - FTS5 trigger sync: after INSERT, new row is searchable
    - FTS5 trigger sync: after UPDATE, old content is NOT searchable, new content IS searchable
    - FTS5 trigger sync: after DELETE, removed content is NOT searchable
    - Dedup threshold direction: identical content produces rank < 5.0 (strong match)
    - Dedup threshold direction: weakly related content produces rank >= 5.0 or no match (not a dedup hit)
    - OR-based matching: "Dinner is at 7pm" matches a memory containing "Dinner Time: 6pm" (shared terms)
  </behavior>
  <action>
    Create `tests/memory/fts.test.ts` following the pattern in `tests/knowledge/fts.test.ts`:

    - For dedup threshold tests, insert a memory then search with similar/different content and assert rank threshold behavior
    - For trigger sync tests, insert -> verify searchable, update content -> verify old gone + new found, delete -> verify gone
    - For special chars test, search with queries like `"hello (world)"` and `"NOT OR AND"` -- should not throw
    - Note on BM25: single-document corpus scores differ from production. Test DIRECTION (strong match rank < weak match rank), not exact values. The dedup threshold test verifies that identical/near-identical content produces rank < 5.0.

  <action>
In src/ai/tool-handler.ts, in the "update_knowledge" case, add a validation check AFTER extracting fields but BEFORE the existing getById call. The check should verify that the `changes` object has at least one key (i.e., at least one of title, summary, content, or tags was provided). If `changes` is empty, return a JSON error response:

```
{ "error": "No fields to update. You must provide at least one of: title, summary, content, tags. For recipe modifications, retrieve the current content with get_knowledge_item, modify it, then provide the full updated content field." }
```

Move the `changes` object construction (lines 145-149) ABOVE the `getById` call so the emptiness check happens before any database access. The logic becomes:
1. Extract id, title, summary, content, tags, change_description from input
2. Build changes object with only defined fields
3. If changes is empty, return error immediately (no DB call)
4. Then proceed with getById, update, changelog as before

In tests/ai/tool-handler.test.ts, add a new describe block "tool-handler update_knowledge" with a test "rejects update with no substantive fields":
- Create mock deps with a knowledgeRepository that has getById and update as vi.fn()
- The mock db needs an insert method returning { values: () => ({ run: vi.fn() }) }
- Call handleToolCall("update_knowledge", { id: 1, change_description: "make it spicier" })
- Assert the result JSON contains error with "No fields to update"
- Assert knowledgeRepository.getById was NOT called (the guard fires before DB access)

Also add a test "accepts update with content field" to confirm valid calls still work:
- Mock getById to return { id: 1, title: "Test", content: "old content", summary: "s", tags: ["recipe"] }
- Mock update to return { id: 1, title: "Test", content: "new content", summary: "s", tags: ["recipe"] }
- Call handleToolCall("update_knowledge", { id: 1, content: "new content", change_description: "updated" })
- Assert result JSON contains message with "Updated" and no error

In src/ai/tools.ts, update the update_knowledge tool description (currently starts with "Update an existing knowledge item. Provide the item ID and only the fields that changed."). Replace the description with:

"Update an existing knowledge item. Provide the item ID and the fields to change. " +
"You MUST include at least one substantive field (title, summary, content, or tags) -- " +
"calling with only id and change_description will be rejected. " +
"IMPORTANT: the content field replaces the ENTIRE content -- for partial recipe updates, " +
"first retrieve the current content with get_knowledge_item, modify the specific part, " +
"then send back the complete updated content. Does NOT require re-confirming the whole " +
"recipe for minor changes."

In src/ai/system-prompt.ts, in the RECIPE_VARIATIONS_PROMPT constant, update the IN-PLACE MODIFICATIONS section. Currently step 3 says:
"3. Use update_knowledge to save the modified content back with a change_description"

Replace step 3 with:
"3. Use update_knowledge with the full updated content field AND a change_description. ALWAYS provide the full updated content field -- change_description alone does NOT modify the recipe."

Also in the INLINE SUBSTITUTION NOTES section, the last bullet says:
"To add variations: retrieve the recipe with get_knowledge_item, append the Variations section, update with update_knowledge"

Replace with:
"To add variations: retrieve the recipe with get_knowledge_item, append the Variations section to the content, then call update_knowledge with the complete updated content field"

  <action>
1. Create `src/conversation/types.ts`:
   - `ConversationTurn`: { id, chatId, userId, text, direction ("in"|"out"), createdAt }
   - This maps directly to the existing `messages` table schema. No new table needed -- we reuse the existing messages table from Phase 1.

2. Create `src/conversation/context-builder.ts`:
   - `buildConversationContext(turns: ConversationTurn[], tokenBudget: number): Anthropic.MessageParam[]`
   - Implements sliding window per research Pattern 5: work backwards from most recent turn, accumulate until token budget is reached.
   - Use `estimateTokens()` from `../knowledge/token-budget.js` for each turn.
   - Map direction "in" -> role "user", direction "out" -> role "assistant".
   - If no turns fit, return empty array (first message in conversation).
   - Session boundary: 4 hours (per research suggestion). If there's a gap of >4 hours between turns, treat earlier turns as a different session and stop including them. This is Claude's discretion per user decision -- 4 hours is a practical default for meal planning (morning vs evening conversations are distinct sessions).
   - Return `Anthropic.MessageParam[]` that can be prepended to the current user message.
   - IMPORTANT: The returned array must maintain alternating user/assistant message ordering as required by the Anthropic API. If the oldest included turn is "assistant", prepend it to maintain valid ordering (assistant messages can start a sequence only if followed by user). If consecutive same-role messages exist (from batching), merge them.
   - Import `Anthropic` type from `@anthropic-ai/sdk` for MessageParam.

3. Update `src/ai/claude-client.ts`:
   - Keep existing `sendMessage()` method unchanged (backward compatibility).
   - Add new `sendMessageWithTools()` method to the returned object:
     ```
     async sendMessageWithTools(
       messages: Anthropic.MessageParam[],
       tools: Anthropic.Tool[],
       onToolCall: (name: string, input: Record<string, unknown>) => Promise<string>,
       maxIterations?: number
     ): Promise<ClaudeResponse>
     ```
   - Implements manual tool use loop per research Pattern 1:
     a. Call `client.messages.create()` with model, max_tokens: 2048, system prompt (with cache_control), messages, and tools.
     b. If response.stop_reason === "end_turn", extract text and return ClaudeResponse.
     c. If response has tool_use blocks, extract them. For each, call `onToolCall(name, input)`.
     d. Construct tool_result blocks: `{ type: "tool_result", tool_use_id, content: result }`.
     e. Append assistant response + user tool_results to messages array (per research pitfall 3: all tool_results in ONE user message immediately after assistant).
     f. Loop back to (a) with updated messages. Max iterations default 3 (per research example).
     g. Safety: if max iterations reached, do one final call WITHOUT tools to force a text response.
   - Return final ClaudeResponse with aggregated token usage across all iterations.
   - The system prompt should be passed through `buildSystemPrompt()` as before. No changes to system prompt content needed yet -- knowledge context is delivered via tools, not system prompt injection.

4. Update `src/ai/system-prompt.ts`:
   - Add a new section to the system prompt that instructs Claude about its knowledge tools:
     ```
     <tools>
     - You have access to a knowledge base of the user's recipes, preferences, and cooking notes
     - When the user asks about their recipes, preferences, or past meals, use search_knowledge to find relevant items
     - After searching, use get_knowledge_item to get full details for items you want to reference
     - You can search multiple times with different queries to find what you need
     - Don't mention "searching" or "looking up" to the user -- just naturally reference their information
     - If no relevant knowledge is found, respond naturally without mentioning the search
     </tools>
     ```
   - Keep `buildSystemPrompt()` signature unchanged (returns string). The tools section is part of the persona prompt.
  </action>

  </verify>
  <done>
    Conversation context builder creates Anthropic-compatible message history within token budget. Claude client supports tool use loops with configurable max iterations. System prompt instructs Claude about knowledge tools. Existing sendMessage still works.
  </done>

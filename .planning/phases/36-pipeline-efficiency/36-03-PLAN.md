<objective>
Enhance knowledge deduplication to search recipe/preference content beyond title-only matching, using ingredient overlap for recipes and content similarity for preferences.

Purpose: Current dedup only matches on title (FTS5 title-weighted search). This misses near-duplicate recipes with different titles but identical ingredients ("Mom's Chicken Parm" vs "Chicken Parmesan"), and near-duplicate preferences with different phrasing ("I don't like cilantro" vs "no cilantro please"). Content-aware matching catches these while being conservative (>85% threshold) to avoid false positives.

Output: Content-matching dedup in tool handler, content search utility in fts.ts.
</objective>

  <action>
Enhance the existing dedup check in the `save_knowledge` case of `createToolHandler` to perform content-aware matching beyond title similarity.

Current dedup flow:
1. `searchFts(sqlite, title, householdId, 3)` -- title-weighted search
2. Check for exact title match (case-insensitive)
3. Check for strong BM25 relevance (< 5)

Enhanced dedup flow (replace the existing dedup block):

1. **Title-based search** (existing, keep):
   - `searchFts(sqlite, title, householdId, 3)`
   - Exact title match -> return duplicate_found (unchanged)

2. **Content-based search** (NEW, after title search):
   - Import `searchFtsContent`, `computeIngredientOverlap`, `computeContentSimilarity` from `../knowledge/fts.js`
   - Extract key terms from the incoming content for search. For recipes: extract 3-5 key ingredient names from the content's Ingredients section. For preferences: use the title + first sentence of content.
   - Call `searchFtsContent(sqlite, contentSearchQuery, householdId, 5)` to find content matches
   - For each match, retrieve full content via `retrievalService.getItem(match.id, householdId)`

3. **Overlap scoring** (NEW):
   - Determine if the incoming item is a recipe (tags include "recipe") or preference (tags include "preference")
   - For recipes: call `computeIngredientOverlap(incomingContent, existingContent)` for each content match
     - If overlap > 0.85 (85% threshold per user decision), return duplicate_found with the match details
   - For preferences: call `computeContentSimilarity(incomingContent, existingContent)` for each content match
     - If similarity > 0.85, return duplicate_found with the match details
   - If no content match exceeds threshold, fall through to the existing BM25 relevance check

4. **Existing BM25 fallback** (keep):
   - If the title-weighted top match has relevance < 5, return duplicate_found (unchanged)

5. The duplicate_found response format stays identical -- Claude handles the UX decision silently per existing system prompt instructions. No new "potential duplicate" tagging or extra prompts.

Important implementation notes:
- The content search and overlap computation are wrapped in try/catch (dedup is best-effort, same as existing)
- Only fetch full content for top 3 content matches (limit getItem calls)
- If tags array doesn't include "recipe" or "preference", skip content matching and fall through to the existing title/BM25 dedup
- Keep the `skipDedup` bypass working exactly as before

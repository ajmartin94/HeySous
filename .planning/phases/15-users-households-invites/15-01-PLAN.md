  <action>
Create src/users/ directory with four files following existing module patterns (grocery/, reminders/, feedback/).

**src/users/types.ts** -- TypeScript interfaces:
- `User` interface: `id: number`, `telegramId: string`, `displayName: string`, `username: string | null`, `householdId: string`, `role: 'admin' | 'member'`, `onboardingState: 'registered' | 'complete'`, `createdAt: number`, `updatedAt: number`
- `Household` interface: `id: string`, `name: string`, `createdBy: string`, `createdAt: number`
- `CreateUserParams` interface: `telegramId: string`, `displayName: string`, `username: string | null`, `householdId: string`, `role: 'admin' | 'member'`, `onboardingState: 'registered' | 'complete'`

**src/users/schema.ts** -- Drizzle schema definitions (follows grocery/schema.ts pattern):
- `households` sqliteTable: `id` TEXT PK, `name` TEXT NOT NULL DEFAULT 'My Household', `createdBy` text("created_by") NOT NULL, `createdAt` integer("created_at") NOT NULL
- `users` sqliteTable: `id` INTEGER PK autoincrement, `telegramId` text("telegram_id") NOT NULL unique, `displayName` text("display_name") NOT NULL, `username` TEXT, `householdId` text("household_id") NOT NULL references households.id, `role` TEXT NOT NULL default 'member', `onboardingState` text("onboarding_state") NOT NULL default 'registered', `createdAt` integer("created_at") NOT NULL, `updatedAt` integer("updated_at") NOT NULL

**src/users/init.ts** -- Raw SQL table creation + admin seeding (follows grocery/init.ts pattern):
- `initializeUsers(sqlite: BetterSqlite3.Database, adminUserId: string): void`
- Creates `households` table (CREATE TABLE IF NOT EXISTS) with exact SQL from RESEARCH.md
- Creates `users` table with CHECK constraints on role ('admin', 'member') and onboarding_state ('registered', 'complete')
- Admin seeding: if adminUserId is truthy, check if user exists. If not, create household with `id = adminUserId` (deliberate -- Phase 16 compat), name 'My Household', created_by = adminUserId. Insert user with telegram_id = adminUserId, display_name = 'Admin', household_id = adminUserId, role = 'admin', onboarding_state = 'complete'.
- After seeding, verify admin exists: `SELECT COUNT(*) FROM users WHERE role = 'admin'`. If 0 and adminUserId was provided, throw Error('Admin user seeding failed').

**src/users/repository.ts** -- CRUD functions taking raw `BetterSqlite3.Database` parameter (follows grocery/repository.ts pattern):
- `getUserByTelegramId(sqlite, telegramId): User | undefined` -- SELECT all fields, map snake_case to camelCase
- `createUser(sqlite, params: CreateUserParams): User` -- INSERT and return the created user
- `getHouseholdMembers(sqlite, householdId): User[]` -- SELECT all users WHERE household_id = ?
- `createHousehold(sqlite, params: { id: string, name: string, createdBy: string }): void` -- INSERT
- `getHouseholdById(sqlite, householdId): Household | undefined` -- SELECT
- `updateHouseholdName(sqlite, householdId): void` -- Query all members, generate name using auto-naming logic: 1 member = "Name's household", 2 = "Name1 & Name2's household", 3+ = "Name1, Name2 & Name3's household". UPDATE households SET name = ? WHERE id = ?
- `getAdmin(sqlite): User | undefined` -- SELECT WHERE role = 'admin' LIMIT 1

All functions use `.prepare()` and `.run()` / `.get()` / `.all()` pattern. Import type BetterSqlite3 from "better-sqlite3". Use .js extensions on all imports.

**src/config.ts** -- Add computed `adminUserId` property:
- Add `adminUserId: string` to Config interface
- Set value: `adminUserIds[0] ?? ""`
- This avoids a new env var per RESEARCH.md Pitfall 6

**src/invites/init.ts** -- Raw SQL table creation (follows existing init.ts pattern):

**src/invites/repository.ts** -- CRUD functions:

- All functions use BetterSqlite3.Database parameter, .prepare() pattern, snake_case to camelCase mapping.

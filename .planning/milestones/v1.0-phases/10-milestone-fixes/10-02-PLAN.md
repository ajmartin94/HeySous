<task type="auto">
  <name>Task 1: Wrap tool calls in try/catch with is_error result</name>
  <files>src/ai/claude-client.ts</files>
  <action>
In src/ai/claude-client.ts, the `sendMessageWithTools` method (lines 197-209) calls `onToolCall` for each tool_use block without any error handling. If any tool call throws (e.g., a DB exception during update_knowledge), the entire promise rejects and the pipeline processor's outer catch fires, sending a generic error to the user.

Fix: Wrap each onToolCall invocation in a try/catch. On error, return a tool_result with `is_error: true` and the error message. This lets Claude see the error and recover (e.g., tell the user "I had trouble updating that recipe, let me try again").

Replace the toolResults mapping (lines 198-209) with:

```typescript
const toolResults: Anthropic.ToolResultBlockParam[] =
  toolUseBlocks.map((block) => {
    try {
      const result = onToolCall(
        block.name,
        block.input as Record<string, unknown>,
      );
      return {
        type: "tool_result" as const,
        tool_use_id: block.id,
        content: result,
      };
    } catch (error) {
      const errorMessage = error instanceof Error ? error.message : String(error);
      return {
        type: "tool_result" as const,
        tool_use_id: block.id,
        content: JSON.stringify({ error: errorMessage }),
        is_error: true,
      };
    }
  });
```

This is a minimal change -- only the map callback body gets the try/catch. The rest of the tool loop remains identical.

Note: The `is_error: true` flag is part of the Anthropic API's ToolResultBlockParam type. It tells Claude the tool call failed, so Claude can decide what to do (retry, tell user, skip, etc.).

## Tech Debt

### Phase 37: Streaming
- `getStreamInterruptedMessage()` exported from `messages.ts` but unused — error text inlined in `stream-sender.ts` instead (orphan function)

### Phase 40: Reminder Resilience
- Intentional empty `catch {}` in plan-recipe linking guard (documented as non-blocking by design — FTS search failure should not block saves)

### Cross-Phase
- **429 streaming detection heuristic**: `error.message.includes("429")` in processor.ts instead of type-checked `APIError.status === 429`. Works in practice but could produce false positives if a non-rate-limit error message contains "429". Low risk.
- **Admin role dual mechanism**: API guard uses `config.adminUserIds` (env var) while frontend nav visibility uses DB `users.role`. Aligned for the seeded admin user. If additional admin chat IDs are added to env var later, they get API access but won't see the Admin nav tab (DB role stays `member`). Low risk — single-admin deployment.

**Total: 4 items across 3 areas. None are blockers.**

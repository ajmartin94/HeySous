   - Name: `"add-recipe-time-columns"`

   - Add three nullable INTEGER columns: `prep_time_minutes`, `cook_time_minutes`, `total_time_minutes`
   - Check each column individually before ALTER (idempotent, safe to re-run)
   - **Backfill**: after adding columns, run `parseRecipeTotalMinutes` on all existing recipe content to populate columns. Import `parseRecipeTotalMinutes` from `../reminders/generator.js`. For each knowledge_item that has recipe-tagged content:
     - Query: `SELECT ki.id, ki.content FROM knowledge_items ki JOIN knowledge_tags kt ON kt.knowledge_item_id = ki.id WHERE kt.tag = 'recipe'`
     - For each row, call `parseRecipeTotalMinutes(row.content)` -- this returns total minutes
     - Also parse prep and cook times individually from content lines (`Prep Time:` and `Cook Time:`)
     - UPDATE the row with extracted values (only set non-null results)
   - For the backfill's individual time parsing, extract the `parseTimeToMinutes` function from `src/reminders/generator.ts` -- it's currently a private function. Either: (a) export it alongside `parseRecipeTotalMinutes`, or (b) duplicate a lightweight version in the migration. Prefer option (a): export `parseTimeToMinutes` from generator.ts so both migration and future code can use it.

<task type="auto">
  <name>Task 2: Auto-extract time fields on knowledge save/update and add plan-recipe linking guard</name>
  <files>src/ai/tool-handler.ts, src/ai/tools.ts</files>
  <action>
1. **Update save_knowledge tool definition** in `src/ai/tools.ts`:
   - Add optional parameters to `save_knowledge` input_schema: `prep_time` (number, "Prep time in minutes"), `cook_time` (number, "Cook time in minutes"), `total_time` (number, "Total time in minutes")
   - Add description note: "Time fields are auto-extracted from content for recipes. Explicit values override auto-extraction."
   - Add same three parameters to `update_knowledge` input_schema

2. **Auto-extract time on save_knowledge** in `src/ai/tool-handler.ts`:
   - After recipe completeness validation passes, before the `knowledgeRepository.create()` call
   - Import `parseRecipeTotalMinutes` and `parseTimeToMinutes` from `../reminders/generator.js`
   - For items tagged with "recipe": parse content for prep/cook/total times
   - Content parsing: scan for `Prep Time:`, `Cook Time:`, `Total Time:` lines using same regex as `parseRecipeTotalMinutes`
   - Explicit Claude params (`input.prep_time`, `input.cook_time`, `input.total_time`) override auto-extracted values
   - Compute `total_time_minutes`: if both prep and cook are known, sum them; otherwise use explicit total or parsed total
   - Pass `prepTimeMinutes`, `cookTimeMinutes`, `totalTimeMinutes` to `knowledgeRepository.create()`

3. **Auto-extract time on update_knowledge**:
   - Same logic as save_knowledge: when content is being updated and item has recipe tag, re-extract times
   - Explicit params override auto-extraction
   - Pass time fields to `knowledgeRepository.update()`

4. **Plan-recipe linking guard in save_meal_plan**:
   - After successful `planRepository.savePlan()` call (save succeeds regardless)
   - Check each entry: if `knowledgeItemId` is null/undefined, search for the recipe name in the knowledge base using `searchFts(sqlite, entry.recipe_name, householdId, 1)`
   - Requires `sqlite` to be available (guard: `if (sqlite)`)
   - Collect unlinked matches: `{ name: string, match_id: number, match_title: string }`
   - If any unlinked matches found:
     - Add `unlinked_recipes` array to the JSON response (alongside existing `message`, `plan` fields)
     - Add a `warning` string: "Some entries reference recipes that exist in the knowledge base but aren't linked. Consider re-saving with knowledge_item_id to enable cooking time reminders."
     - Import `logger` from `../logger.js` and log at info level: `logger.info({ householdId, unlinkedRecipes }, "Unlinked recipe matches found in meal plan")`
   - FTS search query construction: use the recipe_name directly as the search query (FTS handles tokenization). Only consider it a match if the top result title closely matches (case-insensitive comparison or very low BM25 score < 5).
   - Validation: add `validatePositiveInt` checks for `prep_time`, `cook_time`, `total_time` in both save_knowledge and update_knowledge validation blocks. These are optional -- only validate if provided (use the existing pattern where `validatePositiveInt` returns null for undefined).
  </action>

  <name>Task 1: Create deep-link builder module and on-demand tool</name>
  <files>src/deep-links/builder.ts, src/ai/tools.ts, src/ai/tool-handler.ts, src/ai/system-prompt.ts</files>
  <action>
1. Create `src/deep-links/builder.ts`:
   - Import `InlineKeyboard` from "grammy" and `config` from "../config.js"
   - Define a `DeepLinkTarget` type: `{ type: "recipe"; recipeId: number } | { type: "recipes" } | { type: "plan" } | { type: "grocery" }`
   - Export `buildDeepLinkKeyboard(targets: DeepLinkTarget[]): InlineKeyboard | null`
     - If `!config.miniAppUrl`, return null
     - For each target, add a row with a `.webApp()` button:
       - `{ type: "recipe", recipeId }` -> `keyboard.webApp("View Recipe", config.miniAppUrl + "/recipes?id=" + recipeId)`
       - `{ type: "recipes" }` -> `keyboard.webApp("View Recipes", config.miniAppUrl + "/recipes")`
       - `{ type: "plan" }` -> `keyboard.webApp("View Plan", config.miniAppUrl + "/plan")`
       - `{ type: "grocery" }` -> `keyboard.webApp("View Grocery List", config.miniAppUrl + "/grocery")`
     - If no targets provided or empty array, return null
   - Export `buildDeepLinksFromToolCalls(toolCalls: Array<{ name: string; input: Record<string, unknown>; result: string }>): DeepLinkTarget[]`
     - This function implements the button density rules from CONTEXT.md:
       - Group tool calls by "link type" (recipe-producing tools, plan tools, grocery tools)
       - Recipe-producing tools: `save_knowledge`, `import_from_url` (extract `id` from result JSON), `get_knowledge_item` (use input `id`)
       - Plan tools: `save_meal_plan`, `get_meal_plan`
       - Grocery tools: `save_grocery_list`, `update_grocery_list`, `get_grocery_list`
       - Single recipe tool call -> `{ type: "recipe", recipeId }` (specific)
       - Multiple recipe tool calls -> `{ type: "recipes" }` (generic)
       - Any plan tool call -> `{ type: "plan" }` (always one button)
       - Any grocery tool call -> `{ type: "grocery" }` (always one button)
       - `attach_deep_link` is NOT handled here -- it's handled separately in its own tool handler
     - Parse result JSON safely (try/catch) to extract IDs. For `save_knowledge` result, extract `id` field. For `import_from_url`, the result is from the URL fetch (not a save), so skip it -- the subsequent `save_knowledge` call will capture the ID.

2. Add `attach_deep_link` tool to `src/ai/tools.ts`:
   - Add a new exported array `DEEP_LINK_TOOLS: Anthropic.Tool[]` with one tool:
     - `name: "attach_deep_link"`
     - `description`: "Attach an inline button that opens the Mini App to a specific view. Use when the user asks to see a recipe, meal plan, or grocery list but no data-changing tool was triggered. For example: 'show me that recipe', 'open my grocery list', 'let me see the plan'. Do NOT use after save_meal_plan, save_grocery_list, or save_knowledge -- those get buttons automatically."
     - `input_schema`: object with properties:
       - `target`: string enum ["recipe", "recipes", "plan", "grocery"], required. "Which Mini App view to open"
       - `recipe_id`: number, optional. "Knowledge item ID of the recipe to open. Required when target is 'recipe'."

3. Add `attach_deep_link` handler to `src/ai/tool-handler.ts`:
   - In the ToolHandlerDeps interface, no new deps needed -- the handler returns a marker JSON that the processor will pick up
   - Add case `"attach_deep_link"` in handleToolCall:
     - Validate `target` is one of the enum values
     - If `target === "recipe"`, validate `recipe_id` is a positive integer
     - Return `JSON.stringify({ deep_link: true, target, recipe_id })` -- the processor will read this marker to send the button

4. Update `src/ai/system-prompt.ts`:
   - In `buildPantryResponsePrompt()`, remove the `groceryLinkInstruction` variable and all references to it. Replace the parameter signature: remove `miniAppUrl?: string` parameter entirely since it's no longer needed for this function. The grocery link is now handled via inline buttons, not plain-text URLs.
   - Remove the `${groceryLinkInstruction}` interpolation from the pantry response template string
   - Remove the line about "include a link to manage it" and "Format the link as a plain URL"
   - Keep the rest of the pantry response prompt intact (conversational pantry walk-through, etc.)
   - Update `buildStaticPrompt()` to call `buildPantryResponsePrompt()` without the miniAppUrl parameter
   - Update `buildStaticPrompt()` signature: keep `miniAppUrl` param since it may still be used by other parts, but stop passing it to `buildPantryResponsePrompt()`
   - Add a brief instruction in the tools prompt section (or a new `<deep_links>` section near the end of static prompt) telling Claude about attach_deep_link:
     - "When the user asks to see or open a recipe, meal plan, or grocery list without triggering a data-changing tool, use attach_deep_link to provide a navigation button."
     - "Do NOT use attach_deep_link after save_meal_plan, save_grocery_list, or save_knowledge -- buttons are attached automatically for those."

5. Wire up the new tool array in `src/pipeline/processor.ts`:
   - Import `DEEP_LINK_TOOLS` from `../ai/tools.js`
   - Add `...DEEP_LINK_TOOLS` to the `allTools` array (after existing tool arrays)

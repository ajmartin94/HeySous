<objective>
Implement 429 retry with exponential backoff and jitter for all Anthropic API calls.

Purpose: When the Anthropic API returns a 429 (rate limit), the pipeline should retry intelligently with exponential backoff and jitter instead of blind immediate retry or failure. The user should see a natural "I'm thinking a little longer on this one..." message after the first retry fails, and a graceful in-character failure message if all retries are exhausted.

Output: Updated claude-client.ts with retry wrapper, updated processor.ts with new retry flow, new message variants in messages.ts.
</objective>

1. In `src/bot/messages.ts`, add two new message functions:

   - "I'm thinking a little longer on this one -- hang tight!"
   - "Taking an extra moment to get this right for you..."
   - "Still on it! Just need a bit more time..."
   These should sound like Sous is genuinely working hard, NOT like a system status message.

   `getResilienceFailureMessage()` -- 3-5 variants of a generic in-character failure message for all resilience failures (429 exhausted, context overflow, etc.). Sous stays in character with an apology:
   - "I got a bit overwhelmed there -- mind sending that again when you're ready?"
   - "Sorry, I couldn't quite pull that together. Try again in a moment?"
   - "My brain's a little overloaded right now. Send it again when you're ready!"
   These are distinct from `getErrorMessage()` which is for general pipeline errors.

2. In `src/ai/claude-client.ts`, add a `retryWithBackoff` utility function (NOT exported -- internal to the module):

   ```typescript
   async function retryWithBackoff<T>(
     fn: () => Promise<T>,
     options: {
       maxRetries: number;
       onRetry?: (attempt: number, delayMs: number) => void | Promise<void>;
       logger?: Logger;
       context?: Record<string, unknown>;
     },
   ): Promise<T>
   ```

   Algorithm (Claude's discretion on exact timing):
   - Base delay: 1000ms
   - Exponential factor: 2 (so delays are ~1s, ~2s, ~4s)
   - Jitter: Add random 0-50% of the computed delay (full jitter)
   - If the error has a `headers` property with `retry-after` (from Anthropic SDK's APIError), parse the Retry-After header value (seconds) and use `max(retryAfterMs, computedDelay)` as the actual delay
   - Call `onRetry` callback before each sleep (to allow the processor to send the "thinking longer" message)
   - On non-429 errors, do NOT retry -- throw immediately
   - The function should detect 429 errors by checking for the Anthropic SDK's `APIError` type with `status === 429`

   Import `Logger` type from pino (just the type, for the optional logger param).

3. In `src/ai/claude-client.ts`, update `createClaudeClient` to accept an optional `logger` parameter:
   ```typescript
   export function createClaudeClient(apiKey: string, model: string, clientLogger?: Logger)
   ```

4. Wrap ALL `client.messages.create()` calls inside `sendMessageWithTools` and `sendMessage` with the `retryWithBackoff` wrapper:
   - `maxRetries: 3`
   - Pass the logger for structured retry logging
   - The `onRetry` callback is NOT wired here (it's just a logger at the client level). The processor-level notification (sending "thinking longer" to user) will be handled separately via the callback.

   Actually, better approach: Instead of wrapping at the client level, expose the retry capability so the processor can provide the `onRetry` callback. Add an optional `onRetry` callback parameter to `sendMessageWithTools`:

   ```typescript
   async sendMessageWithTools(
     messages: Anthropic.MessageParam[],
     tools: Anthropic.Tool[],
     onToolCall: ...,
     maxIterations?: number,
     systemPrompt?: SystemPromptInput,
     onRetry?: (attempt: number, delayMs: number) => void | Promise<void>,
   ): Promise<ClaudeResponse>
   ```

   Inside `sendMessageWithTools`, wrap each `client.messages.create()` call with `retryWithBackoff({ maxRetries: 3, onRetry, logger: clientLogger })`. This covers:
   - The main loop `client.messages.create()` calls (tool use iterations)
   - The final `client.messages.create()` call (max iterations reached, no tools)

   Similarly update `sendMessage` to accept and use `onRetry`.

5. Log each retry attempt with structured data:
   ```
   { attempt, maxRetries, delayMs, retryAfterHeader, householdId (from context), error: message }
   ```
   Log at `warn` level for retries, `error` level when all retries exhausted.

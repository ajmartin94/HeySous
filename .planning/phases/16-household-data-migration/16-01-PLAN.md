**Create `src/db/migrate.ts`:**

Create a new module that performs an idempotent column rename migration. The function `migrateToHouseholdId(sqlite: BetterSqlite3.Database)` should:

1. Check if migration is needed by inspecting `PRAGMA table_info(knowledge_items)` for a column named `chat_id`. If no `chat_id` column exists, return early (already migrated).
2. Run ALL renames inside a single `sqlite.transaction()` call:
   ```sql
   ALTER TABLE knowledge_items RENAME COLUMN chat_id TO household_id
   ALTER TABLE knowledge_changelog RENAME COLUMN chat_id TO household_id
   ALTER TABLE meal_plans RENAME COLUMN chat_id TO household_id
   ALTER TABLE cooking_history RENAME COLUMN chat_id TO household_id
   ALTER TABLE grocery_lists RENAME COLUMN chat_id TO household_id
   ALTER TABLE reminder_settings RENAME COLUMN chat_id TO household_id
   ALTER TABLE reminders RENAME COLUMN chat_id TO household_id
   ALTER TABLE feedback_checkins RENAME COLUMN chat_id TO household_id
   ALTER TABLE token_usage RENAME COLUMN chat_id TO household_id
   ```
3. Log migration success via the pino logger (import from `../logger.js`).

IMPORTANT: Do NOT rename `chat_id` in the `messages` table. Messages keep chat_id because conversation history is per-Telegram-user, not per-household.

IMPORTANT: The `knowledge_tags` table does NOT have a `chat_id` column -- do not attempt to rename it.

**Update `src/db/index.ts`:**

Import `migrateToHouseholdId` from `./migrate.js` and call it AFTER the SQLite instance is created and BEFORE any init functions. This ensures columns are renamed before CREATE TABLE IF NOT EXISTS runs (which would see the table already exists with the new column names and do nothing). Place it after the `pragma` calls and before `initializeFts()`.

**Update all init functions to use `household_id` in CREATE TABLE SQL:**

In each file, find the `CREATE TABLE IF NOT EXISTS` SQL strings and replace `chat_id` with `household_id`. These init functions run on every startup -- for existing databases, the migration already renamed the columns, and for fresh databases, the tables are created with `household_id` from the start.

Files and specific changes:
- `src/knowledge/fts.ts` (`initializeFts`): In the 3 CREATE TABLE statements for `knowledge_items`, `knowledge_tags` (no change needed -- has no chat_id), and `knowledge_changelog`, change `chat_id TEXT NOT NULL` to `household_id TEXT NOT NULL`.
- `src/planning/history.ts` (`initializePlanning`): In CREATE TABLE for `meal_plans` and `cooking_history`, change `chat_id TEXT NOT NULL` to `household_id TEXT NOT NULL`. The `meal_plan_entries` table has no chat_id -- leave it alone.
- `src/grocery/init.ts` (`initializeGrocery`): Change `chat_id` to `household_id` in CREATE TABLE for `grocery_lists`.
- `src/reminders/init.ts` (`initializeReminders`): Change `chat_id` to `household_id` in CREATE TABLE for `reminder_settings` and `reminders`. Also update any UNIQUE constraint references from `chat_id` to `household_id`.
- `src/feedback/init.ts` (`initializeFeedback`): Change `chat_id` to `household_id` in CREATE TABLE for `feedback_checkins`.

Note: The FTS5 triggers in `src/knowledge/fts.ts` only reference `title`, `summary`, `content`, and `id` -- they do NOT reference `chat_id`, so they need no changes. Confirm this while editing.
  </action>

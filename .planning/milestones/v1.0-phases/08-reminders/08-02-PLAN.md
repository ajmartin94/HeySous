**src/reminders/generator.ts** -- Generates reminder rows from meal plan data.

Create `generateReminders(deps: {reminderRepository, planRepository, sqlite, chatId: string, settings: ReminderSettings}): void`

Logic:
1. Delete existing future pending reminders for this chat (`reminderRepository.deleteFutureReminders(chatId)`)
2. Get active plans for the chat (`planRepository.getActivePlans(chatId)`) -- this returns plans with entries
3. Build a map of date -> meals from the plan entries. Also determine the full date range covered by active plans (plan start date to plan end date, typically 7 days each).
4. For each date in the active plan date range (today through end of last active plan):
   a. **Morning summary** (one per day): If `settings.morningEnabled`:
      - If the day HAS meals planned: create ONE morning_summary reminder for that day. Due time = that day at `settings.morningTime` in the user's timezone, converted to UTC. Context JSON includes ALL meals for that day. Use `hasPendingReminder` to avoid duplicates.
      - If the day has NO meals planned (per user decision -- nudge rather than silence): create ONE morning_summary reminder for that day. Due time = same morning time. Context JSON includes `{ type: "no_plan_nudge", date: "YYYY-MM-DD" }` so the sender knows to generate a nudge message like "No dinner planned for tonight -- want to pick something?". Use `hasPendingReminder` to avoid duplicates.
   b. **Prep alerts**: If `settings.prepAlertsEnabled`, for each recipe with a knowledgeItemId, create a prep_alert reminder. Context JSON includes the recipe name and knowledgeItemId (the sender will fetch and analyze the recipe at send time to determine prep needs). Due time = the morning of the day before (at morningTime). If the meal is today, skip prep alert (too late). Context JSON should include: recipeName, knowledgeItemId, mealDate, mealType.
   c. **Start-cooking nudge**: Create a start_cooking reminder for each dinner entry. Due time = that day at `settings.dinnerTime` in the user's timezone, converted to UTC. Context JSON includes recipeName, mealType.

**Timezone conversion helper** (private function in this file):
- `localTimeToUtc(date: string, time: string, timezone: string): Date` -- Takes an ISO date string (YYYY-MM-DD), a time string (HH:MM), and an IANA timezone string. Returns a UTC Date.
- Implementation: Use `Intl.DateTimeFormat` with the timezone to determine the UTC offset, then compute the UTC timestamp. Specifically, construct a Date from the local components, then use the timezone to find the offset. A practical approach: parse the date and time, create a formatted string, and use `new Date()` with timezone awareness.
- Simpler approach per research: construct the local datetime string "YYYY-MM-DDTHH:MM:00", then use a trick -- format it as if in that timezone and compute offset. The cleanest way: use `Date` constructor with the temporal parts, then compute the UTC offset by comparing `date.toLocaleString('en-US', {timeZone})` round-tripped back to Date.

**Only generate reminders for today and future dates.** Skip past dates entirely.

**src/ai/tools.ts** -- Add `REMINDER_TOOLS` export after GROCERY_TOOLS:

Three tools:
1. `get_reminder_settings` -- Get current reminder settings for this chat. No required inputs.
2. `update_reminder_settings` -- Update reminder settings. Optional fields: timezone (string, IANA), morning_time (string, HH:MM), dinner_time (string, HH:MM), morning_enabled (boolean), prep_alerts_enabled (boolean), muted_until (string, ISO date or null to unmute). At least one field required per user decision -- but technically optional in schema (tool is flexible).
3. `regenerate_reminders` -- Regenerate all pending reminders from current meal plans. Used after plan changes or setting updates. No required inputs.

Follow the exact same Anthropic.Tool[] pattern as KNOWLEDGE_TOOLS, PLAN_TOOLS, and GROCERY_TOOLS.

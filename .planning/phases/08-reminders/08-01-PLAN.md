<task type="auto">
  <name>Task 2: Reminder repository with factory function</name>
  <files>src/reminders/repository.ts</files>
  <action>
Create `createReminderRepository(sqlite: BetterSqlite3.Database)` factory function. Uses raw SQLite queries via `sqlite.prepare()` -- same pattern as grocery/repository.ts. Import types from ./types.js.

Define raw row interfaces (ReminderSettingsRow, ReminderRow) and mapper functions internally (same pattern as grocery/repository.ts mapList/mapItem).

**Settings methods:**
- `getSettings(chatId: string): ReminderSettings | null` -- Get settings for a chat. Returns null if no settings exist yet.
- `upsertSettings(chatId: string, updates: Partial<{timezone: string, morningTime: string, dinnerTime: string, morningEnabled: boolean, prepAlertsEnabled: boolean, mutedUntil: Date | null}>): ReminderSettings` -- Insert or update settings. Use SQLite `INSERT ... ON CONFLICT(chat_id) DO UPDATE`. Add UNIQUE constraint on chat_id in init.ts (update init.ts to include this).
- `getOrCreateSettings(chatId: string): ReminderSettings` -- Get existing or create with defaults. Calls upsertSettings with empty updates if no row exists.
- `getAllActiveSettings(): ReminderSettings[]` -- Get all settings where either morningEnabled or prepAlertsEnabled is true, and (mutedUntil is null OR mutedUntil < now). Used by the poller to know which chats need reminders.

**Reminder methods:**
- `createReminder(params: {chatId: string, type: ReminderType, dueAt: Date, contextJson: string}): Reminder` -- Insert a new pending reminder.
- `getDueReminders(): Reminder[]` -- Query reminders where `status = 'pending' AND due_at <= unixepoch()`. Ordered by due_at ASC. This is the core poller query.
- `markSent(id: number, generatedText: string): void` -- Update status to 'sent', set sent_at to now, store generated_text.
- `markFailed(id: number): void` -- Update status to 'failed'.
- `deleteFutureReminders(chatId: string): void` -- Delete all pending reminders for a chat where due_at > now. Used when regenerating reminders after plan changes.
- `deleteAllPending(chatId: string): void` -- Delete all pending reminders for a chat. Used on full regeneration.
- `hasPendingReminder(chatId: string, type: ReminderType, dueAtStart: Date, dueAtEnd: Date): boolean` -- Check if a pending reminder of this type already exists in the time window. Prevents duplicates during regeneration.

**Important:** Update `src/reminders/init.ts` to add `UNIQUE(chat_id)` constraint on reminder_settings table.

Boolean fields: Store as 0/1 in SQLite, convert to boolean in mapper (same pattern as grocery checked field).
Timestamps: Store as unix epoch integers, convert to Date in mapper (same as grocery pattern: `new Date(row.created_at * 1000)`).

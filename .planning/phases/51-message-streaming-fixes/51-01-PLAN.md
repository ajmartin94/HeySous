  <name>Task 2: Update processor to use accumulated text instead of response.text override</name>
  <files>src/pipeline/processor.ts</files>
  <action>
1. **Stop passing `cleanText` as finalize override.** The stream sender's accumulated text is the source of truth for multi-turn content. Change the finalize call (around line 722-726) from:
   ```typescript
   await streamSender.finalize(cleanText, ...)
   ```
   to:
   ```typescript
   await streamSender.finalize(undefined, deepLinkKeyboard ? { reply_markup: deepLinkKeyboard } : undefined)
   ```
   This lets finalize use the accumulated text (which includes all turns + tool status hints).

2. **Extract onboarding markers from accumulated text** instead of `response.text`. Change the marker extraction (around line 653) to work on the accumulated text AFTER streaming completes but BEFORE finalize:
   - Get accumulated text via `streamSender.getAccumulatedText()`
   - Run `extractOnboardingMarker()` on it
   - If markers found, mutate the accumulated text — add a new `setAccumulatedText(cleaned)` method to stream-sender, OR better: run extractOnboardingMarker on accumulated text and if it differs, pass the cleaned version as the finalize override

   **Recommended approach:** After the streaming try/catch block (after `response` is set), extract markers from accumulated text:
   ```typescript
   const accText = streamSender.getAccumulatedText();
   const { text: cleanAccText, completedPhase } = extractOnboardingMarker(accText);
   ```
   Then at finalize time, pass `cleanAccText` as override ONLY if marker extraction changed it (i.e., `cleanAccText !== accText`). Otherwise pass `undefined` to use raw accumulated text:
   ```typescript
   const finalizeText = cleanAccText !== accText ? cleanAccText : undefined;
   await streamSender.finalize(finalizeText, ...);
   ```

3. **Use accumulated text for DB save** instead of `cleanText`. Change the messages insert (around line 729-736) to save `cleanAccText` (the marker-stripped accumulated text) instead of `cleanText`:
   ```typescript
   db.insert(messages).values({
     chatId, userId,
     text: cleanAccText,
     direction: "out" as const,
   }).run();
   ```

4. **Keep the non-streaming (fallback) path unchanged.** The `response.text` / `cleanText` path for non-streaming still works correctly since there's no stream sender accumulation in that case.

5. **Verify the empty-text check** still works: `cleanAccText.trim()` instead of `cleanText.trim()` for the streaming path.

<task type="auto">
  <name>Task 1: Create sanitization utility and tests</name>
  <files>src/ai/sanitize.ts, tests/ai/sanitize.test.ts</files>
  <action>
Create `src/ai/sanitize.ts` exporting a `sanitizeForPrompt(text: string): string` function that:
1. Strips ALL HTML tags using a regex like `/<[^>]*>/g` replaced with empty string. This removes `<b>`, `</b>`, `<script>`, self-closing tags, etc.
2. Strips null bytes (`\0`) and ANSI escape sequences (`\x1B\[[0-9;]*[a-zA-Z]` pattern).
3. Trims the result (collapsed whitespace at edges).
4. Returns the cleaned string. Empty input returns empty string.

Also export a `sanitizeAndLog(text: string, field: string, logger: Logger): string` wrapper that:
1. Calls `sanitizeForPrompt(text)`.
2. If the result differs from the input, logs at `info` level with structured fields: `{ field, originalLength: text.length, sanitizedLength: result.length, event: "prompt_sanitization" }` and a `security` tag. Use the Pino child logger pattern: `logger.info({ ... }, "Sanitized user input for prompt")`.
3. Returns the sanitized result.

Import the Logger type from `pino` (the project uses pino).

Create `tests/ai/sanitize.test.ts` with tests covering:
- Plain text passes through unchanged
- HTML tags are stripped: `<b>John</b>` -> `John`, `<script>alert(1)</script>` -> `alert(1)`
- Nested/malformed HTML: `<b><i>text</i></b>` -> `text`
- Control characters stripped: null bytes, ANSI escapes like `\x1B[31mred\x1B[0m` -> `red`
- Mixed content: HTML + control chars in one string
- Empty string returns empty string
- String with only tags returns empty string (after trim)
- Normal cooking-related text (ingredient names, unicode) passes through unchanged
- Unicode characters like emoji, accented letters are preserved

Use Vitest. Import with `.js` extension per project convention.

  <done>sanitizeForPrompt strips HTML tags and control characters. sanitizeAndLog logs when sanitization modifies input. All test cases pass.</done>

Modify `src/ai/system-prompt.ts` to sanitize user-controlled text at the two injection points:

1. **In `buildDynamicContext`**: Import `sanitizeForPrompt` from `./sanitize.js`. Before interpolating `userName` into the prompt string, sanitize it: `const safeName = userName ? sanitizeForPrompt(userName) : undefined;`. Use `safeName` in the template string instead of `userName`. Note: We use `sanitizeForPrompt` (not `sanitizeAndLog`) here because the processor's logger is not available in the system prompt module. Logging is handled separately (see note below).

2. **In `buildPreferenceContext`**: Sanitize each preference's `title` and `summary` before interpolating. In the `lines.map()` callback, apply `sanitizeForPrompt(pref.title)` and `sanitizeForPrompt(pref.summary)` when building the line string.

Note on logging: The system prompt module does not have access to a logger instance. Sanitization logging will be done at the processor level in a future observability phase. For now, silent sanitization is sufficient -- the locked decision says "silent neutralization from user's perspective", and structured logging is a "should have" that can be wired when the processor gets observability (Phase 34).

- Ensure existing tests still pass (the sanitization should be transparent for clean input).

Keep imports using `.js` extensions per project convention.
